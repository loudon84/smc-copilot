# PRD v7.6：Copilot Desktop Hermes Agent MCP Host Mode 优化方案

版本：v7.6
定位：Copilot Desktop 只作为用户操作入口与 hermes-agent 配置控制面；任务执行、MCP 调用、文档生成、本地落盘均由 hermes-agent 完成。

---

## 1. 核心结论

v7.6 必须收敛为以下链路：

```text
copilot-desktop Chat
  → hermes-agent API_SERVER :8642
  → hermes-agent 内部 MCP Client
  → nodeskclaw Expert MCP Gateway
  → expert skill / mcp tool
  → hermes-agent stream / run events
  → copilot-desktop 展示过程与结果
```

不再允许：

```text
copilot-desktop
  → nodeskclaw Expert MCP Gateway
```

---

## 2. 产品定位

### 2.1 Copilot Desktop 职责

```text
1. 管理 hermes-agent 配置
2. 管理 hermes-agent mcp_servers
3. 管理 Chat 页面用户交互
4. 管理 expert / skill 选择 UI
5. 将 expert / skill 选择转换为 prompt hint
6. 消费 hermes-agent API_SERVER stream / run events
7. 展示工具调用过程、专家过程、最终输出、本地文档路径
```

### 2.2 hermes-agent 职责

```text
1. 作为 Agent Runtime
2. 读取 mcp_servers 配置
3. 通过内部 MCP Client 连接 nodeskclaw Expert MCP Gateway
4. 执行 MCP tool / expert skill
5. 接收 MCP progress / structured tool output
6. 生成最终回答
7. 将文档写入本地 workspace
8. 通过 API_SERVER 输出 stream / run events
```

### 2.3 nodeskclaw 职责

```text
1. 暴露 Expert MCP Gateway
2. 提供 expert skill tools
3. 执行 expert skill
4. 若存在内部 SSE timeline，必须转换为：
   - MCP progress
   - structured tool output
5. 不要求 desktop 订阅 nodeskclaw SSE
```

## 7. Prompt Hint 规则

### 7.1 输入

```ts
interface ExpertPromptHintInput {
  userMessage: string;
  expertName?: string;
  expertId?: string;
  skillName?: string;
  mcpServerName?: string;
  permissionMode?: "default" | "readonly" | "write";
  outputPreference?: "markdown" | "docx" | "pdf";
}
```

### 7.2 输出

```text
请优先使用已配置的 Hermes MCP Server「nodeskclaw_expert_gateway」中的 expert skill「manufacturer-profiling」完成任务。

执行要求：
1. 通过 hermes-agent 内部 MCP Client 调用工具。
2. 不要求 desktop 直接调用任何远端 Expert Gateway。
3. 如果工具返回过程信息，请以工具进度形式展示。
4. 如果生成报告，请保存到当前 Hermes workspace。
5. 最终回答必须包含生成文档的本地路径。

用户任务：
{userMessage}
```

### 7.3 禁止拼接字段

```text
_routing
_execution
route_config
eventSseUrl
artifactUrl
desktop_direct_call
```

## 8. hermes-agent MCP 配置管理

### 8.1 配置目标

Copilot Desktop 写入当前 profile 的 hermes-agent 配置：

```text
~/.hermes/config.yaml
~/.hermes/.env
```

多 profile：

```text
~/.hermes/profiles/{profile}/config.yaml
~/.hermes/profiles/{profile}/.env
```

### 8.2 推荐 config.yaml

```yaml
mcp_servers:
  nodeskclaw_expert_gateway:
    enabled: true
    url: "${NODESKCLAW_EXPERT_MCP_URL}"
    headers:
      Authorization: "Bearer ${NODESKCLAW_EXPERT_MCP_TOKEN}"
      X-Client: "copilot-desktop"
      X-Desktop-Id: "${COPILOT_DESKTOP_ID}"
    timeout: 600
    tools:
      include:
        - manufacturer-profiling
        - customer-profiling
        - enterprise-risk-analysis
```

### 8.3 推荐 .env

```env
NODESKCLAW_EXPERT_MCP_URL=http://nodeskclaw.local/api/mcp/expert-gateway
NODESKCLAW_EXPERT_MCP_TOKEN=xxxx
COPILOT_DESKTOP_ID=desktop-xxxx
```

## 11. Chat 发送逻辑

### 11.1 旧逻辑

```text
if selectedExpert + selectedSkill + useExpertGateway:
  call nodeskclaw Expert Gateway directly
else:
  send to hermes-agent
```

### 11.2 新逻辑

```text
if selectedExpert + selectedSkill:
  message = buildExpertPromptHint(userMessage, selectedExpert, selectedSkill)
else:
  message = userMessage

sendToHermesAgent(message)
```

### 11.3 伪代码

```ts
async function handleSend(input: string) {
  const finalMessage =
    selectedExpert && selectedSkill
      ? buildExpertPromptHint({
          userMessage: input,
          expertName: selectedExpert.name,
          skillName: selectedSkill.name,
          mcpServerName: "nodeskclaw_expert_gateway",
          permissionMode,
        })
      : input;

  await hermesChatStream.send({
    message: finalMessage,
    profile: activeProfile,
    sessionId: activeSessionId,
  });
}
```

## 16. 实施步骤

### Phase 1：删除 direct gateway 主链路

```text
1. Chat 页移除 useExpertGateway 业务分支
2. send 时不再调用 callCatalogSkill
3. 禁用 useExpertTaskStream
4. UI 隐藏 direct task accepted 卡片
5. 保留 debug 能力但不进入业务路径
```

验收：

```text
发送 expert skill 消息时，Network / Main log 中不能出现 desktop → nodeskclaw tools/call。
```

### Phase 2：MCP 配置写入 hermes-agent

```text
1. 新增 hermes-mcp-config-service
2. 写 config.yaml mcp_servers
3. 写 .env token
4. reload 或 restart hermes-agent
5. 读取 hermes-agent 已注册 MCP tools
```

验收：

```text
配置 nodeskclaw_expert_gateway 后，hermes-agent 能发现对应 MCP tools。
```

### Phase 3：Chat prompt hint 改造

```text
1. 新增 buildExpertPromptHint
2. expert / skill 选择只影响 prompt
3. 所有消息统一走 hermesAPI.sendMessage
4. 增加 Prompt Hint Preview
```

验收：

```text
选择 manufacturer-profiling 后，发送到 hermes-agent 的消息包含明确工具使用提示。
```

### Phase 4：stream process 展示

```text
1. 扩展 tool progress parser
2. 增加 ToolProgressTimeline
3. 支持 MCP structured output 展示
4. 最终回答正常进入 assistant message
```

验收：

```text
nodeskclaw MCP tool 返回 progress 时，Chat 页面显示处理过程。
```

### Phase 5：文档卡片

```text
1. hermes-agent 按 prompt 保存文档
2. final response 返回本地路径
3. desktop 识别路径
4. 渲染 LocalDocumentCard
```

验收：

```text
任务完成后 Chat 页面显示本地文档卡片，点击可打开文件或所在目录。
```

### Phase 6：清理旧代码

```text
1. 删除业务入口里的 direct gateway API
2. 删除旧 expert accepted UI
3. 删除旧 artifactUrl 下载路径
4. 保留 debug 页面或彻底移除
```

