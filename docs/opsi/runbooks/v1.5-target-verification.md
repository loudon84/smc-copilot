# v1.5 Target verification recovery

Rollout HEALTHY/ROLLED_BACK is written only from persisted TargetVerification.

If a target is UNKNOWN_BLOCKED:

1. Confirm Action Result exists for the rollout `actionId` (continuation uses parent request id).
2. Refresh Inventory from opsiconfd; stale snapshots fail closed.
3. Confirm ProductOnClient exact version/package and owner.
4. Confirm Work smoke reference/digest is present (opsi-control stores the reference only).
5. Re-run the rollout reconciler. Same digest is idempotent; a different digest is conflict.

Do not inject `facts` success flags. Repair requires a new Campaign if desired state drifted.
