# v1.4 User continuation relay

User-context completion travels only on the OPSI channel.

## Endpoint

- Bootstrap task arguments include the real OPSI `ClientId`, parent `RequestId`, Gateway port, and manifest digest.
- `Initialize-HermesHome.ps1` writes `continuations/{requestId}.json`. `clientId=local` is forbidden.
- Outbox fields: parent request, status/error, inventory summary, content digest, redacted, trust level `OPSI_AUTHENTICATED_CHECKSUM`.

## Control

- Reconciler seeing `USER_CONTEXT_PENDING` queues an internal `custom=status` poll. It does not SSH/WinRM to the Endpoint.
- Product `status` relays pending continuation markers into instlog (`parent_request_id`, `result_kind`, `content_sha256`) then emits current status.
- Reconciler validates poll→parent, client id, and digest, then closes the original setup/update. Duplicate success is not overwritten by an older RUNNING marker.

Restart API/worker/client and replay the same outbox; the parent request must converge without a side channel.
