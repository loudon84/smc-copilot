# OPSI v1.7.1 Client Release Builder

Engineering command for a lab Client Release. Live evidence remains operator-only.

## One command

```powershell
.\scripts\build-client-release.ps1 `
  -HermesRepo "D:\git\hermes-agent" `
  -OpsiClientInstaller "D:\packages\opsi-client-agent-installer.exe" `
  -SigningKeyRef "D:\secure\smc-release.pem" `
  -Output "D:\smc-release" `
  -HermesZip "D:\smc-release\hermes-0.20.2-windows-amd64.zip" `
  -OpsiPackage "D:\smc-release\smc-hermes-agent_1.7.1-1.opsi"
```

Config SOT: `release/client-release.yaml`. Runtime profile SOT: `release/hermes-runtime-profiles.yaml` (`smc-managed` only).

## Stages

| Stage | Meaning |
| --- | --- |
| `preflight` | R00-R02 freeze smc-copilot + hermes-agent (dirty fails unless `-AllowDirty`, which forces `liveEligible=false`) |
| `work` | R03 `npx nx run work:package-win` unless `-WorkDist` already has setup/portable exe |
| `hermes` / `runtime` | Hermes managed offline bundle + Runtime Artifact v3 sign (`tools/release/hermes`, `makepackage.py`) |
| `opsi-stage` / `opsi-package` | Deterministic stage + **native** `opsi-makepackage` + extract/read-back. No zipfile production `.opsi`, no Docker builder in this release |
| `assemble` / `verify` / `all` | Client Release layout + `smc.client-release.v1` + SHA256SUMS. Any mismatch is not READY |

Hermes ZIP must not contain `python.exe`, Node runtime, `.venv`, `node_modules`, or secrets. Endpoint install creates a slot venv and uses `pip install --no-index`.

## RB Live Gates (operator)

- RB-01 Local hermes-agent Git → signed managed bundle
- RB-02 Offline venv install on Windows with preinstalled Python 3.12 x64 + Node 22
- RB-03 native `opsi-makepackage` + extract/read-back
