# v1.2 Pilot target nomination and preflight

Use only after v1.1 Live Evidence is `proven / GO`. Until then this checklist is a dry-run template.

## Nomination

- Explicit client ids, 10–20 Windows 10/11 endpoints, single OPSI 4.3 Server/Depot.
- Each endpoint `control-owner` is `{ "hermes": "opsi" }` with no Salt/Runtime/direct conflict.
- Previous Product/package, artifact digest, config revision, and owner baseline are retrievable.
- User Binding (SID + account), Scheduled Task, disk ≥ 512 MiB, Gateway `:8642` recently healthy.
- No other active mutation Action or Campaign.

## Snapshot

1. Materialize canonical sorted client ids.
2. Record snapshot SHA-256; do not re-expand inventory queries at runtime.
3. Confirm Canary = first 2 ids, remaining batches ≤ 5, same digest ⇒ same batches.
4. Any membership change requires a new Campaign.

## Preflight

`POST /api/v1/opsi/rollouts/{id}/preflight` with `If-Match`. Any unknown/unsafe/unrollbackable target stays `INELIGIBLE` and the Campaign must not be approved. Preflight TTL is 1 hour; start/resume after expiry must re-run.
