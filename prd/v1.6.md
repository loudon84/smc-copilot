# SMC Copilot 产品需求文档 PRD v1.6

## Desktop Chat Capability Closure & Runtime-owned Hermes Feature Bridge

**版本：** v1.6
**项目：** `loudon84/smc-copilot`
**参考项目：** `loudon84/copilot-desktop`
**本地参考源码：** `apps/desktop/references/copilot-desktop`
**实施范围：**

* `apps/desktop`
* `services/runtime`
* `contracts`
* `packages/runtime-client-ts`

# 1. 项目背景

`smc-copilot` 已完成从原 `copilot-desktop` 单体式 Hermes Desktop 架构向：

```text
Desktop
  ↓
Runtime Service
  ↓
Hermes Agent / Gateway
```

的职责拆分。

当前 Monorepo 已明确：

```text
apps/desktop
services/runtime
contracts
packages/runtime-client-ts
```

其中 Desktop 为 Electron + React，Runtime 为 FastAPI。

当前正式边界定义为：

```text
Renderer
  ↓
Preload
  ↓
Desktop Main
  ↓
@smc/runtime-client
  ↓
Runtime :8765
  ↓
Hermes Agent / Gateway
```

Renderer 不直接访问 Runtime HTTP，Desktop 不再承担 Hermes Agent Control Plane。

v1.6 不改变该架构。

本版本目标是在该架构下，补回原 `copilot-desktop` Chat 中已经验证有效的 Hermes Agent 交互能力，同时删除当前迁移过程中残留的 Desktop→Hermes 数据访问。

# 2. v1.6 核心目标

v1.6 完成四个目标：

### G1. 补齐 Hermes Agent 原生 Chat 能力

重点恢复：

* Agent Slash Command
* Side Question `/btw`
* Session Context Folder
* Worktree
* Session Model Override
* Voice STT fallback
* Reasoning Effort
* Fast / Service Tier
* Chat Readiness

### G2. 完成 Desktop Thin Client 收口

Desktop 不再直接：

* 读取 `~/.hermes/state.db`
* 读取/修改 Hermes `config.yaml`
* 读取 Hermes `.env`
* 管理 Hermes Gateway Port
* 调用 Hermes Gateway `/v1/*`
* 保存 Hermes Session Attachment Index
* 建立 Hermes Dashboard WebSocket
* 启动 Hermes Python 进程

### G3. Runtime 成为 Chat Control/Data Plane

Runtime 统一承担：

* Session
* Chat Run / Turn
* Event
* Queue
* Interaction
* Command
* Background Turn
* Attachment
* Session File
* Context Folder
* Session Model
* Chat Preferences
* Voice Transcription
* Hermes Gateway RPC

### G4. 参考源码只用于能力迁移

允许：

```text
apps/desktop/references/copilot-desktop
```

作为 Cursor 的源码参考。

禁止：

```ts
import ... from ".../references/copilot-desktop/..."
```

Reference 目录不得进入生产运行依赖。

# 3. 原 copilot-desktop Chat 架构分析

## 3.1 原调用链

原项目实际上是：

```text
Renderer Chat
   │
   ├─ window.hermesAPI
   │
   ├─ Dashboard WebSocket JSON-RPC
   │
   └─ Desktop File APIs
   ↓
Electron Main
   ↓
hermes.ts
   ↓
Local Hermes Gateway
   ↓
Hermes Agent
```

`hermes.ts` 自己解析：

* profile
* Gateway Port
* API_SERVER_KEY
* remote / ssh / local mode
* Hermes Python
* Gateway URL
* Hermes Home

并直接与 Hermes API 交互。

Dashboard 模式则由 Renderer 自己维护 WebSocket JSON-RPC Client，包括：

* connect
* request
* timeout
* notification
* reconnect/error

等逻辑。

这些属于旧架构实现，不得复制到新的 Desktop。

# 7. Side Question / Background Agent

原 Chat 的：

```text
/btw
/bg
/background
```

不是普通 Prompt。

旧实现调用 Hermes：

```text
prompt.background
```

创建独立 Background Agent。

特征：

* 主 Agent 可以继续工作；
* Side Question 不进入主 Busy Queue；
* 不阻塞主 Turn；
* 不改变主会话上下文；
* Background 完成后通过 `background.complete` 返回结果。

当前 Runtime Durable Chat 已有：

* ChatRun
* ChatTurn
* Queue
* SSE
* Event
* Snapshot
* Recover

但没有恢复该 Background Prompt 语义。

这是 v1.6 P0 功能。

# 8. Context Folder

原 Chat 可以为每个 Session 绑定：

```text
contextFolder
```

Session 恢复时自动恢复目录。

新会话可重新选择目录。

Local：

```text
selectFolder()
```

Remote：

```text
RemoteFolderPicker
```

Hermes 创建 Session 时可以把 Context Folder 作为：

```text
cwd
```

传入执行 Session。

当前 `smc-copilot` 的共享 Chat Contract 已经定义：

```ts
contextFolder?: string
```

但是目前：

```text
ChatSurface
    ↓
useChatController
    ↓
ChatTurnRequest
```

没有真正构建 `contextFolder`。

ServeChatRuntimeAdapter 调用 Runtime 时也没有把 `request.contextFolder` 继续传给 Runtime。

因此目前属于：

> Contract 已存在，但功能链路没有完成。

这是 v1.6 P0 功能。

# 10. Session Model Override

旧 Chat 支持：

```text

        +
Session Model Override
```

用户在某个 Chat 中选择模型，只影响当前 Session。

恢复 Session 时：

```text
restore session model override
```

且不会写回：

```text
config.yaml default model
```

当前 `aiosModelsAdapter`：

### Model List

已经优先通过 Runtime。

这是正确的。

### Session Model

当前读取的是 Runtime Chat Model Config，但本质仍偏 Instance 配置；

写入 Session Model 时仍调用：

```ts
window.hermesDefaultChat.setSessionModel(...)
```

因此 Session Model Ownership 尚未迁移完成。

v1.6 必须完成 Runtime Session Model Setting。

# 11. Voice Input

原 Chat 的 Voice Input 有两级：

```text
SpeechRecognition
       ↓ fail
MediaRecorder
       ↓
Hermes STT
```

Electron 中如果 Chromium SpeechRecognition 不可用，会：

1. `MediaRecorder` 录音；
2. 每 2.5 秒做一次增量转写；
3. 停止后做 Final Transcription；
4. 调用 Hermes STT。

原 Main 还能调用：

```text
/api/audio/transcribe
```

必要时回退到本地 Hermes Python transcription。

当前新 Chat 只有：

```text
SpeechRecognition
webkitSpeechRecognition
```

Electron 下实际可用性明显下降。

v1.6 应恢复 MediaRecorder fallback，但调用链改成：

```text
Desktop MediaRecorder
       ↓
Runtime
       ↓
Hermes /api/audio/transcribe
```

Desktop 不再直接调用 Hermes Python。

# 26. FR-03 Background Side Question

```text

/bg
/background
```

```text

         +

         ↓
主 Chat 不停止
```

新增：


```json

  "parentTurnId": "...",

  "message": "..."
```

```text
run_kind = main | background

parent_turn_id
```

### Events

新增：

```text
background.started
background.completed
background.failed
```

```text

```

也可以接入。

### 强制规则

Background Turn：

* 不改变 Main Run `runState`
* 不进入 Main Queue
* 不改变 Main Session Context
* Main Turn 可继续 Streaming
