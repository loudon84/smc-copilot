# SMC Copilot Chat UI Layout 参考复刻规范

**参考源：** `apps/desktop/references/copilot-desktop`
**目标：** `apps/desktop/src/renderer/src/modules/chat`
**范围：** 只处理 Chat Layout、视觉层级、组件组合和前端交互，不改变 v1.6 Runtime / Hermes 架构。

---

# 1. 核心结论

`copilot-desktop` Chat 好用的核心不是某个组件，而是以下 5 条原则：

1. **Conversation 永远是页面第一视觉主体**
2. **Composer 与右侧工作面板相互独立**
3. **Thinking / Tool / Approval 属于消息流，不属于页面 Header**
4. **模型、工作目录、推理强度等操作全部靠近 Composer**
5. **Session Files / Preview / Worktree 是辅助 Workspace，不抢占 Chat 主布局**

因此不要以当前 `smc-copilot ChatSurface` 继续增加 Slot。

应该先重新建立原版 Layout Shell。

# 2. copilot-desktop 原始布局

原 `Chat.tsx` 的核心结构实际上非常简单：

```text
ChatContainer
│
├── ConfigHealthBanner               条件显示
│
├── ChatBody                         flex: 1
│   │
│   ├── ChatMessages                 flex: 1
│   │
│   ├── SessionFilesPanel            optional
│   │
│   ├── WorktreePanel                optional
│   │
│   ├── FilePreviewPanel             optional
│   │
│   └── WebPreviewPanel              optional
│
├── ChatInputArea                    固定底部区域
│   │
│   ├── QueuedMessages
│   └── ChatInput
│
├── DropOverlay
│
└── RemoteFolderPicker
```

源码中 `chat-body` 关闭后，才进入 `chat-input-area`。因此 Composer 与右侧工作面板属于两个不同布局层。

这是复刻时最重要的一点。

# 4. Composer 位置错误

当前：

```text
ChatBody
├── ChatMain
│   ├── Messages
│   └── Composer
└── RightPanel
```

当 RightPanel 从 0 → 400px 时：

```text
Messages width ↓
Composer width ↓
```

输入框会不断改变宽度。

旧版：

```text
ChatBody
├── Messages
└── RightPanels

Composer
```

RightPanel 只影响：

```text
Messages Workspace
```

不改变底部输入区整体布局。

因此必须恢复：

> Composer outside ChatBody。

---

# 5. RightPanel 容器模型错误

当前：

```text
aside.chat-right-panel
├── SessionFiles
├── FilePreview
└── Worktree
```

而 `.chat-right-panel` 自己已经定义：

```css
width: min(400px, 42%);
min-width: 240px;
max-width: 42%;
```

也就是说：

> 外层容器控制宽度，内部 Panel 又自己控制布局。

当前 CSS 即采用此模型。

旧版不是这种模式。

旧版：

```text
chat-body
├── chat-messages
├── session-files-panel
├── worktree-panel
├── file-preview-panel
└── web-preview-panel
```

每个 Panel 自己拥有宽度。

因此不存在统一：

```text
chat-right-panel
```

这一抽象。

# 6. 消息区域宽度策略不同

旧版：

```css
.chat-messages {
    flex: 1;
    overflow-y: auto;
    padding: 24px;
}
```

`chat-body`：

```css
display: flex;
flex: 1;
overflow: hidden;
```

消息本身：

```css
.chat-message {
    display: flex;
    gap: 12px;
    width: 100%;
    max-width: 85%;
}
```

用户消息：

```css
margin-left: auto;
flex-direction: row-reverse;
```

而当前新增了：

```css
--chat-content-max: 960px;
```

并用：

```text
ChatContentRail
```

统一把 Messages / Composer 居中限制到 960px。

同时 Bubble 又进一步：

```css
max-width: min(720px, 100%);
```

结果容易出现：

```text
Window
 └── 960 Content Rail
      └── 920 Message
           └── 720 Bubble
```

视觉空间被连续压缩。

这是当前 Chat 看起来比旧版“窄、碎、小”的主要原因之一。

# 21. Tool / Reasoning 不做普通 Bubble

旧版将 Reasoning：

```text

```

做成可折叠区域。

```text

```

也折叠。

100 次 Tool Call 不会出现：

```text

```

而是：

```text

   ├─ Search
   ├─ Read File
   └─ Write File
```

`HistoryRow` 就是这种双层折叠模型。

必须作为 SMC Chat 的标准。

# 73. 验收标准

## Layout

必须满足：

* Composer 不随 Session Files 打开而缩窄；
* Composer 不随 File Preview 打开而缩窄；
* Composer 永远处于 Chat 底部；
* Messages 为独立 Scroll Container；
* Right Panels 不产生第二层 Generic Right Panel；
* Header ≤ 40px；
* Diagnostics 不占主 Layout；
* Context Folder 不占独立横条。

---

## Message

必须满足：

* User 右对齐；
* Agent 左对齐；
* User 无 Avatar；
* Agent 一个 Turn 一个 Avatar；
* Reasoning 可折叠；
* Tool Burst 自动分组；
* Tool Item 二级展开；
* Hover 才显示 Action；
* Markdown 排版与 Code/Table 正常。

---

## Composer

必须满足：

* 单一 Composer Card；
* Textarea 无独立 Border；
* 最大高度 120px；
* Enter Send；
* Shift+Enter 换行；
* IME 正常；
* Slash Command Palette 正常；
* Prompt History 正常；
* Attachment Strip 正常；
* Drag Drop 正常；
* Quick Ask 正常；
* Loading 时 Send 切换 Stop。

---

## Workspace

必须满足：

* Session Files 默认 220px；
* Worktree 默认 240px；
* Preview 默认约 440px；
* Panel Resize；
* Width Persistence；
* Preview Maximize；
* Maximize 只覆盖 ChatBody；
* Composer 始终可用。

# 74. 最终原则

这次 UI 优化不要继续：

```text
给现有 ChatSurface 加 CSS
```

而应当：

```text
恢复 copilot-desktop 的 Layout 骨架
             +
保留 smc-copilot 的新能力
```

最终关系应该是：

```text
copilot-desktop
    ↓
Layout / Interaction Reference

smc-copilot
    ↓
Runtime / Expert / Team / Document Capabilities
```

即：

> **旧版负责定义“Chat 应该怎么用”，新版负责提供“Chat 能做什么”。**

不要让新增的 Runtime、Expert、Team、Diagnostics、Workspace 能力改变 Chat 的基础交互模型。
