## Salt Ring 0 Pilot Orchestration & 5-Endpoint Controlled Rollout

版本：v2.4  
项目：smc-copilot  
代码基线：1f12445  
唯一 Salt Master：192.168.102.104  
目标规模：5 台 IT / 开发 Windows Endpoint  
观察周期：全部 Endpoint 稳定后连续 7 天

## 1. 目标

v2.4 将 v2.3.1 的单 Endpoint 能力升级为可持久化、可暂停、可恢复、可审计的 Ring 0 灰度系统，并完成 5 台真实 Endpoint 的受控迁移。

交付结果：

1. Salt Control 使用真实 PostgreSQL 事务边界。
2. Job、Returner、Observer、Rollout 在服务重启后可恢复。
3. 5 台 Endpoint 按 1 → 2 → 2 批次迁移。
4. 每批次满足观察门禁后才允许推进。
5. 全部 5 台连续观察 7 天。
6. 输出 v2.5 HA Readiness / Ring 1 的 Go / No-Go。

## 3. 生产阻塞项

### P0

1. Production AppState 使用长期 boot Session 构建全部 Repository 和 Service。
2. Job Worker 在最长 300 秒 Salt 等待期间只续租一次，默认 Lease 为 60 秒。
3. Job reclaim 后会重新发布 Salt Function，没有优先查询已有 JID。
4. Enrollment Worker 发布 JID 后又调用 ping / sync_all / highstate，存在重复执行。
5. Job Operation 没有类型化参数；install 无法传 Artifact，configure/start/stop/restart 映射错误。
6. Handover Job 只调用 smc_handover.commit，未执行完整 Runtime 停止、Gateway 启动、健康和 Work Probe。
7. Returner 请求字段为 returns/payload，Salt Control API 要求 items/payloadRedacted。
8. Observer 只从进程内 active_rollouts 查找 Rollout，服务重启后无法自动暂停。
9. Live Canary 对变更操作只输出 gates_ready_awaiting_job，不会调用 Job API。
10. Live Canary 仅凭回滚脚本存在就把 Runtime fallback 标为通过。

### P1

1. Observer 的 1h / 6h / 24h 只是最近快照，不是时间窗口聚合。
2. Endpoint Status 的 rollout 和 gateway_health 固定为空。
3. Rollout Target 已有表结构，但未形成 Job、Target、批次之间的编排。
4. Rollout 和 Secret 仍使用进程内 IdempotencyStore。
5. CI 没有真实 PostgreSQL 服务，也没有执行完整 alembic upgrade head。
6. eAuth 仍授权完整 @runner 和 @wheel。
7. Master README 与 failover 配置仍保留 Ring 0 必须第二 Master 的旧约束。
8. v2.3.1 baseline 仍引用旧 Commit 和错误的 Live Canary 文件。
9. Test / Lab 默认构建两个 Fake Master，无法覆盖单 Master 生产路径。

## 6. 功能需求

## 6.1 Request-scoped Unit of Work

生产 API 每个请求必须：

1. 从 Session Factory 创建独立 AsyncSession。
2. 构建该请求专属 RepositoryBundle 和 Service。
3. 成功时 commit。
4. 异常时 rollback。
5. 最终 close。

禁止：

- 使用长期 Session 处理业务请求。
- 在 AppState 中保存长期 SQLAlchemy Repository。
- Worker 在等待 Salt HTTP 时长期占用数据库事务。

Readiness Probe 创建短生命周期 Session；应用关闭时 dispose Engine。

## 6.2 持久化幂等

Rollout、Secret、Migration 和 Job 全部使用数据库幂等记录。

规则：

- 唯一键：scope + request_id。
- 保存 request hash、response snapshot、created_at、expires_at。
- 相同 request_id 且 payload 不同返回 409。
- 服务重启和多实例部署后结果一致。
- Secret Response Snapshot 不保存明文 Secret。

## 6.3 Job Invocation

新增类型化 Operation Payload：

- install：release_id、artifact_ref、config_revision。
- upgrade：release_id、rollback_release_id。
- configure：config_revision。
- start / stop / restart：gateway task identity。
- health / diagnose：probe policy。
- handover / remigrate：migration revision、work probe policy。
- rollback：rollback type、snapshot revision、release fallback。

禁止接受任意 Salt Function、arg 或 kwarg。

固定映射：

| Operation | Salt Function |
| --- | --- |
| install | 受控 Hermes State |
| upgrade | smc_hermes.upgrade |
| configure | 受控 Config State |
| start | smc_hermes.start |
| stop | smc_hermes.stop |
| restart | smc_hermes.restart |
| health | smc_hermes.health |
| diagnose | smc_hermes.doctor |
| handover | smc_handover.migrate |
| remigrate | smc_handover.remigrate |
| rollback | smc_handover.rollback |

## 6.4 Lease 和 JID 恢复

规则：

1. Salt 发布成功后立即持久化 JID。
2. 等待结果期间每 20 秒续租。
3. 续租使用独立短事务。
4. Reclaim 发现已有 JID 时只查询结果，不重新发布。
5. 只有确认未发布过 Salt Function 才允许首次发布。
6. 终态不可被迟到结果覆盖。
7. Salt 结果解析读取目标 Minion 的真实 Return。
8. 超时进入 result_pending，不直接重复发布。

## 6.5 Enrollment Worker

Enrollment 后置步骤统一进入 Durable Job Engine：

- test.ping
- saltutil.sync_all
- state.highstate

每步只允许一个 JID；进程重启后从 JID 恢复。禁止 local_async 后再次调用相同同步函数。

## 6.6 Handover

smc_handover.commit 只保留为原子 Owner Primitive，不再代表完整 Handover。

新增真实入口：

- smc_handover.migrate
- smc_handover.remigrate
- smc_handover.rollback

真实 Handover：

1. Preflight。
2. Snapshot Runtime、Hermes Home、Gateway Task、Control Owner。
3. 检查 Salt、Pillar、Release 和绑定用户。
4. 准备 Hermes Release，不提前切换 Owner。
5. 停止旧 Gateway。
6. 停止 Runtime Gateway Ownership。
7. 原子切换 Owner=salt。
8. 启动绑定用户 Gateway Task。
9. 检查 Gateway Health。
10. 执行 Work Probe。
11. 写入 Migration Marker。

任一步失败必须恢复 Snapshot 和 Runtime Ownership。

## 6.7 Returner

统一请求字段：

- requestId
- items
- jid
- endpointId
- function
- success
- payloadRedacted

要求：

- API 与 Returner 使用同一生成 Contract。
- Returner 成功后删除加密 Spool。
- Spool 重试指数退避。
- JID Return 更新 Control Job。
- Returner 与 Job Poll 竞争时保持幂等。
- 不保存 Secret、Token、Private Key 或用户正文。

## 6.8 Persistent Observer

新增持久化数据：

- endpoint_observations
- rollout_observations
- control_plane_incidents

每 60 秒记录：

- Master / salt-api 可用性。
- Minion heartbeat age。
- Gateway health。
- Job success / failure / duration。
- Rollout Target 状态。
- Owner conflict。
- Release / Config drift。

窗口：

- 15m
- 1h
- 6h
- 24h
- 7d

服务重启不得丢失窗口。

## 6.9 Endpoint Status

Endpoint Status 必须返回：

- heartbeat
- gateway_health
- control_owner
- current_release
- desired_release
- current_revision
- desired_revision
- migration_phase
- rollout_id
- rollout_target_state
- last_job
- last_error
- last_observed_at

禁止使用固定 null 作为已支持字段。

## 6.10 Ring 0 Rollout

创建 Rollout 时解析并冻结 5 个 Endpoint ID。Snapshot 创建后禁止自动增加设备。

批次：

- Batch 1：1 台，观察至少 24 小时。
- Batch 2：2 台，Batch 1 通过后启动，观察至少 24 小时。
- Batch 3：2 台，Batch 2 通过后启动。
- 全部 5 台稳定后开始 7 天观察。

Target 状态：

- pending
- preflight
- ready
- deploying
- verifying
- observing
- succeeded
- failed
- rollback_pending
- rolled_back
- skipped

Rollout 状态：

- draft
- waiting_approval
- approved
- running
- paused
- aborting
- aborted
- observing
- completed
- failed
- rolled_back

## 6.11 Approval

进入 Batch 1 前需要三个不同 OIDC Subject：

- Release Owner。
- Platform Owner。
- Security Owner。

修改 Target、Release、Config 或 Threshold 后审批失效。Batch 2 和 Batch 3 根据前一批次证据人工 Advance。

## 6.12 Auto Pause

满足任一条件自动暂停：

- Master 连续 180 秒不可用。
- P0 > 0。
- P1 > 0。
- Secret Leak > 0。
- Signature Bypass > 0。
- Owner Conflict > 0。
- Duplicate Salt Publish > 0。
- Gateway Availability < 99.9%。
- Highstate Success < 99.5%。
- Config Apply Success < 99.5%。
- Rollback Rate > 1%。
- Work Critical Flow 失败。

暂停后允许 Diagnose 和经审批 Rollback，禁止 Advance 和新部署。Master 恢复后不得自动 Resume。

## 6.13 Rollback

支持：

- 单 Endpoint Rollback。
- 当前 Batch Rollback。
- 整个 Rollout Rollback。

执行：

1. 暂停 Rollout。
2. 取消未发布 Job。
3. 恢复 Runtime Ownership。
4. 恢复 Release / Config Snapshot。
5. 验证 Gateway 和 Work。
6. 记录 Target、Batch 和 Rollout 结果。

## 6.14 Live Canary

Live Canary 必须：

1. 校验 TLS、Master Fingerprint、Minion Key、Release Signature、Pillar Revision。
2. 调用 Salt Control Job / Migration API。
3. 等待 JID 终态。
4. 执行真实 Work Probe。
5. 对 Runtime fallback 执行实际切换和验证。
6. 生成不可变证据。

禁止以脚本存在代替功能通过，禁止对变更操作停在 awaiting_job。

## 6.15 Work Ring 0 Probe

每台 Endpoint 验证：

- Work 启动不依赖 Runtime 8765。
- Availability-only 模式不启动或重启 Gateway。
- Chat HTTP / WebSocket。
- Session 创建、继续和历史读取。
- Attachment 上传。
- Managed Files。
- Slash Command。
- Gateway 中断后的用户提示。

CI 固定运行 Ring 0 定向测试；全量 Work Test 失败数量不得增加。
