# 2. Hotfix 背景

v1.4 已完成 Server 面板和大部分 Runtime-first 架构调整，当前 Settings 已收敛为：

```text
Runtime Service
Hermes Runtime
Hermes Instances
Expert MCP Gateway
Runtime Logs & Diagnostics
```

当前 `ServerPanel` 已经只组合上述五个 Section，Portal Runtime / Copilot Serve 面板已经退出 Renderer 主 UI。

但实际运行仍存在三类明显的架构遗留。

### 问题 A：Desktop 仍启动 MCP Proxy

执行：

```bash
npm run dev:desktop
```

仍输出：

```text
[MCP PROXY] Listening on http://127.0.0.1:18781
```

根因是 Desktop `registerMcpIpc()` 启动时仍执行：

```ts
void startMcpRuntimeProxy();
```

而 `mcp-runtime-proxy.ts` 中仍由 Electron Main 自建 HTTP Server，并固定监听 `18781`。

当前 `main/index.ts` 也仍注册：

```text
registerMcpIpc
seedDefaultMcpServers
registerMcpSkillGatewayRuntimeIpc
```

说明 MCP Control Plane 尚未完全迁出 Desktop。

---

### 问题 B：`dev:runtime` 只启动 Runtime Service，没有真正接管本机 Hermes

当前：

```bash
npm run dev:runtime
```

执行：

```text
alembic upgrade head
→ scripts/dev_bootstrap.py
→ uvicorn :8765
```

但目前 `dev_bootstrap.py` 对 `HERMES_DEV_EXECUTABLE` 只做：

```text
检测
hermes --version
打印提示
```

并没有真正：

```text
注册 RuntimeVersion
激活 RuntimeVersion
创建 Default Instance
```

源码甚至明确输出：

```text
Runtime should register this Hermes via install/activation (dev).
```

之后如果 RuntimeVersion 不存在，只打印：

```text
No default Hermes instance and no RuntimeVersion row yet.
```

所以出现：

```text
Runtime :8765          Ready
RuntimeVersion         0
Hermes Instance        0
Gateway                unavailable
Execution              Attention
```

属于当前实现的必然结果。

---

### 问题 C：Readiness v2 已实现，但 Desktop 仍使用旧 degraded 判定

Runtime 已经正确拆成：

```text
service
execution
maintenance
expertMcp
```

其中：

```text
Service:
database
migration
secretStore
jobWorker

Execution:
hermes
instance
gateway

Maintenance:
manifest
disk
```

但 Desktop handshake 获取 `/runtime/readiness` 后，仍继续执行旧判断：

```ts
status.status === "degraded"
||
status.hermesInstalled === false
||
Object.values(status.checks).some(...)
```

然后直接：

```text
RuntimeDegraded
ready=false
```

这导致当前截图出现逻辑矛盾：

```text
Connection    RuntimeDegraded
Service       Ready
Execution     Attention
Maintenance   Attention
```

---

### 问题 D：Runtime Logs UI 已存在，但 Runtime 没有真正输出日志文件

Desktop 已经有 `RuntimeLogsSection`，Runtime Tab 调用 `getDiagnosticsLogs()`。

Runtime `/diagnostics/logs` 会读取：

```text
runtime-service.log
```

不存在时再寻找其他 `.log`，仍没有则返回：

```json
{
  "lines": [],
  "truncated": false
}
```

但是当前 Runtime Logging 只使用：

```python
PrintLoggerFactory(file=sys.stderr)
```

即：

```text
Runtime
→ Terminal stderr
```

没有创建：

```text
runtime-service.log
```

所以：

```text
Terminal 有日志
Desktop Runtime Logs 没日志
```

也是当前实现的必然结果。

# 21. Local Hermes Discovery

发现顺序：

```text
1. HERMES_DEV_EXECUTABLE

2. shutil.which("hermes")

3. 明确允许的开发环境候选路径
```

优先使用 PATH。

伪代码：

```python
def resolve_local_hermes() -> Path | None:
    override = os.getenv("HERMES_DEV_EXECUTABLE")

    if override:
        return validate_path(override)

    discovered = shutil.which("hermes")

    if discovered:
        return Path(discovered).resolve()

    return None
```
