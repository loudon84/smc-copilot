# 4.3 P0：不能直接删除现有 runtimeFetch

当前 Desktop `runtime-http-client.ts` 已经实现：

```text
Bearer Device Token
Legacy Token
X-Desktop-Version
X-Runtime-Api-Version
X-Request-ID
Idempotency-Key
query
JSON
FormData
AbortSignal
Error Envelope Mapping
DesktopRuntimeError
```

而新 `@smc/runtime-client` 当前 transport 较简单。

因此禁止：

```text
直接删除 runtimeFetch
→ 全面替换 createRuntimeClient
```

这会造成功能回退。

### v1.1 解决方案

把 Runtime Client 分为：

```text
Generated Contract
        ↓
Runtime Domain Client
        ↓
Runtime Transport
```

定义：

```ts
interface RuntimeTransport {
  request<T>(request: RuntimeRequest): Promise<T>;
  stream(request: RuntimeStreamRequest): AsyncIterable<RuntimeSseMessage>;
}
```

Desktop 实现：

```text
DesktopRuntimeTransport
```

复用现有：

```text
runtime-http-client
runtime-sse-client
runtime-auth-store
runtime-error-mapper
```

然后：

```text
@smc/runtime-client
      ↑
DesktopRuntimeTransport
```

这样保留现有：

```text
鉴权
幂等
requestId
错误映射
SSE 重连
Last-Event-ID
```

能力。

```text
verify version
→ build manifest
→ upload manifest
```

不是完整 Release。

v1.1 改为三套组件流水线。

---

# 21.1 Desktop Release

Tag：

```text
desktop-vX.Y.Z
```

必须验证：

```text
Tag Version
==
apps/desktop/package.json version
```

然后：

```text
npm ci
Desktop CI
Electron Build
Windows Installer
SHA256
Upload Artifact
Release Manifest
```

产物：

```text
SMC-Copilot-X.Y.Z-setup.exe
SHA256SUMS
release-manifest.json
```

---

# 21.2 Runtime Release

Tag：

```text
runtime-vX.Y.Z
```

必须：

```text
Tag
==
pyproject.toml version
```

产物：

```text
wheel
Runtime Windows Installer
Runtime Manifest
SHA256
```

禁止将：

```text
runtime-install-windows.ps1
```

称为 package target。

当前脚本是 Provision / Install Scaffolding。

Nx 重命名：

```text
runtime:provision-windows
```

新增真正：

```text
runtime:package-windows
```

---

# 21.3 Contract Release

Tag：

```text
contracts-vX.Y.Z
```

必须：

```text
Tag
==
contracts.bundleVersion
```

产物：

```text
openapi.yaml
runtime-events/*.json
runtime-client-ts/dist
contract-manifest.json
SHA256
```

```json
{
  "sourceCommit": "...",

  "desktop": {
    "version": "...",
    "artifact": "...",
    "sha256": "..."
  },

  "runtime": {
    "version": "...",
    "artifact": "...",
    "sha256": "..."
  },

  "contracts": {
    "bundleVersion": "...",
    "runtimeApi": "...",
    "runtimeEvents": "..."
  },

  "compatibility": {
    "minimumDesktopVersion": "...",
    "minimumRuntimeVersion": "..."
  }
}
```

Manifest 必须读取真实构建产物，不能提前猜 artifact filename。

# 29. Definition of Done

SMC Copilot Monorepo v1.1 完成的标准不是“两个项目位于同一个 Git 仓库”。

必须满足：

```text
一个 Runtime Contract
+
一个 Runtime Client
+
一个 Chat Runtime
+
一套 Capability 语义
+
一套 Version 事实源
+
一个可回放 Event Store
+
一套真正 Blocking 的 CI
+
三套独立可发布 Artifact
```

最终调用关系：

```text
Renderer
   ↓
Preload
   ↓
Desktop Main
   ↓
@smc/runtime-client
   ↓
Runtime :8765
   ↓
Hermes Instance
   ↓
Hermes Gateway
```

Production 中不允许：

```text
Renderer → Runtime HTTP

Desktop Business Module → hand-authored Runtime URL

Desktop → Hermes CLI

Desktop → ~/.hermes direct modification

Desktop → Profile Chat legacy route
```

v1.1 完成后，`smc-copilot` 才从“合并后的代码仓库”升级为真正统一的 Desktop + Runtime 产品工程。
