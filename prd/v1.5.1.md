| 项目               | 内容                                                                               |
| ---------------- | -------------------------------------------------------------------------------- |
| 产品               | SMC Copilot                                                                      |

---

# 2. 问题背景

v1.5 已完成 Hermes Supervisor 基础建设：

```text
RuntimeVersion
      ↓
HermesInstance
      ↓
Desired / Observed State
      ↓
GatewayProcessManager
      ↓
Gateway Health
      ↓
Ownership Verification
```

当前运行时出现：

```text
GET http://127.0.0.1:8642/health
→ HTTP 200
```

说明：

```text
Gateway Port      Listening
Gateway HTTP      Reachable
Gateway Health    Healthy
```

但 Runtime 同时记录：

```text
GATEWAY_PORT_OWNERSHIP_CONFLICT
```

Instance 状态：

```text
Desired      running

Process      missing
Gateway      unknown
Ownership    unknown

Health       unhealthy
Execution    unavailable
```

因此当前问题不是：

```text
Runtime 无法访问 Hermes
```

而是：

```text
Runtime 可以访问 Hermes Gateway
        ↓
但无法证明该 Gateway Process 属于当前 Instance
        ↓
Supervisor 拒绝接管
        ↓
Execution Ready = false
```

---

# 3. Hotfix 定位

v1.5.1 只解决四件事：

```text
1. Persistent Gateway Fingerprint

2. Runtime Restart Ownership Reconcile

3. Development Safe Adoption

4. Uvicorn Reload Orphan Prevention
```

不修改：

```text
Chat Runtime

Task Runtime

AgentExecutionKernel

Expert

Expert Team

MCP Protocol

Model

Session

Memory

Artifact

Approval
```

---

# 4. 核心原则

必须继续保持 v1.5 的安全边界：

> **Gateway Health 不等于 Gateway Ownership。**

即：

```text
GET /health = 200
```

只能证明：

```text
API Reachable
API Authenticated
Gateway Healthy
```

不能单独证明：

```text
Process belongs to Runtime
```

因此禁止：

```text
8642 /health == 200
→ 直接 ownership=owned
```

---

# 5. 当前故障模型

最可能出现：

```text
Runtime Worker A
     ↓
starts Hermes Gateway PID 20000
     ↓
Gateway :8642
     ↓
Uvicorn reload / Runtime restart
     ↓
Worker A exits
     ↓
Gateway PID 20000 remains
     ↓
Runtime Worker B starts
     ↓
in-memory Process Handle lost
     ↓
8642 occupied
     ↓
/health = 200
     ↓
ownership unknown
     ↓
GATEWAY_PORT_OWNERSHIP_CONFLICT
```

根本问题：

> Gateway Ownership 当前没有完整跨 Runtime Process 生命周期恢复。

# 7. Persistent Gateway Fingerprint

## 7.1 目标

Gateway Ownership 不能仅存在：

```text
GatewayProcessManager._handles
```

或：

```text
asyncio.subprocess.Process
```

内存对象。

必须将可恢复的 Process Fingerprint 保存到 Runtime DB。

---

# 7.2 Fingerprint 字段

建议扩展 `HermesInstance`：

```text
gateway_pid

gateway_process_create_time

gateway_executable_path

gateway_command_hash

gateway_started_at

gateway_started_by_runtime

gateway_owner_runtime_id

gateway_fingerprint_version
```

现有：

```text
pid
gateway_port
```

暂时兼容。

---

# 7.3 Runtime Identity

新增 Runtime 启动标识：

```text
runtime_instance_id
```

每次 Runtime Service 启动生成新的：

```text
UUID
```

例如：

```text
2d4bc030-....
```

用于日志和 Process Ownership 追踪。

但注意：

```text
runtime_instance_id
```

变化不能让历史 Gateway 自动失去 Ownership。

因为 Runtime 重启后需要进行：

```text
ownership recovery
```

---

# 7.4 Gateway 启动时记录

Gateway 启动成功后立即获取：

```text
PID
Process Create Time
Executable Path
Command Line
Port
Profile
RuntimeVersion
Instance ID
```

持久化：

```json
{
  "pid": 23120,
  "processCreateTime": 1786241100.12,
  "executablePath": "C:\\...\\hermes.exe",
  "gatewayPort": 8642,
  "profileName": "default",
  "runtimeVersionId": "...",
  "instanceId": "...",
  "startedByRuntime": true
}
```

# 9. Ownership State

正式状态：

```text
unknown
owned
adopted
foreign
stale
conflict
```

含义：

### `owned`

当前 Runtime 启动并仍持有完整 Process Handle。

### `adopted`

Runtime restart 后，根据持久化 Fingerprint 成功重新确认。

功能上视同：

```text
owned
```

但审计需要区分。

### `foreign`

确认端口进程不是 Runtime 管理的 Hermes。

### `stale`

数据库保存的 Fingerprint 已失效。

### `conflict`

目标 Gateway Port 被无法安全接管的进程占用。

@dataclass

# 12. Persistent Ownership Recovery

Runtime Startup：

```text
load HermesInstance
      ↓
desired=running
      ↓
fingerprint exists
      ↓
GatewayOwnershipService.inspect()
```

---

# 12.1 Case A — Fingerprint 完整匹配

满足：

```text
stored PID alive

AND

stored processCreateTime == live createTime

AND

stored executable == live executable

AND

PID listens on gatewayPort

AND

command line matches Hermes Gateway

AND

profile matches

AND

authenticated /health succeeds
```

处理：

```text
ownership = adopted

process_state = alive

api_state = healthy

healthy = true

status = running
```

然后：

```text
gateway.process.adopted
```

日志。

---

# 12.2 关键原则

此时无需：

```text
stop Gateway
restart Gateway
```

Runtime 直接恢复：

```text
supervision
```

---

# 13. Case B — Stored PID 不存在

如果：

```text
stored PID dead
```

并且：

```text
gatewayPort free
```

处理：

```text
ownership = stale

clear fingerprint

desired=running
→ start new Gateway
```

---

# 14. Case C — PID 被重用

如果：

```text
PID same
```

但：

```text
processCreateTime different
```

则：

```text
ownership = stale
```

**绝对禁止：**

```text
terminate PID
```

即使 PID 数字和 DB 一致。

---

# 15. Case D — Fingerprint PID 与 Port Listener 不一致

例如：

```text
stored PID = 1234

8642 listener PID = 5678
```

处理：

```text
stored fingerprint = stale
```

然后继续判断：

```text
5678 是否符合 Safe Adoption
```

不能直接：

```text
kill 5678
```

---

# 16. Case E — Foreign Process

如果端口监听进程：

```text
不是 Hermes

或

executable 不匹配

或

command line 不匹配 Gateway

或

profile 不匹配
```

处理：

```text
ownership = foreign

process_state = foreign

status = error

GATEWAY_PORT_OWNERSHIP_CONFLICT
```

Runtime：

```text
DO NOT KILL
```

---

# 17. Restart Reconcile

升级：

```text
reconcile_instances_on_boot()
```

正式顺序：

```text
HermesInstance
      ↓
Desired State
      ↓
Load Fingerprint
      ↓
Inspect Stored Process
      ↓
Inspect Port Listener
      ↓
Check Gateway Health
      ↓
Ownership Decision
      ↓
Adopt / Start / Conflict
```

---

# 18. Reconcile 决策矩阵

| Desired | Fingerprint | Port    | Health    | 处理         |
| ------- | ----------- | ------- | --------- | ---------- |
| running | valid       | owned   | healthy   | Adopt      |
| running | stale       | free    | -         | Start      |
| running | missing     | free    | -         | Start      |
| running | invalid     | foreign | healthy   | Conflict   |
| running | invalid     | foreign | unhealthy | Conflict   |
| stopped | valid owned | owned   | healthy   | Stop       |
| stopped | foreign     | foreign | any       | Do nothing |

# 19. Safe Adoption

## 19.1 目标

解决开发环境：

```text
uvicorn --reload
```

导致的 orphan Gateway。

但不能降低生产安全。

---

# 19.2 配置

新增：

```env
HERMES_GATEWAY_SAFE_ADOPTION_ENABLED=false
```

Production 默认：

```text
false
```

Development 默认：

```text
true
```

或：

```env
HERMES_DEV_ALLOW_SAFE_ADOPTION=true
```

仅 development 生效。

---

# 20. Safe Adoption 适用范围

仅：

```text
deployment_mode = development
```

允许。

Production：

```text
unknown Gateway
→ conflict
```

不自动 adoption。

---

# 21. Safe Adoption 必须全部满足

未知 Listener 只有同时满足：

```text
Port == instance.gateway_port

Executable == active RuntimeVersion executable

Command Line contains:
gateway run

Command Line contains:
--external-supervisor

Profile matches Instance

Hermes Home matches expected environment

Authenticated /health == 200

No conflicting persisted owner

No second Runtime claims same Instance
```

才能：

```text
safe_to_adopt = true
```

---

# 22. Safe Adoption 成功

处理：

```text
ownership = adopted

persist new fingerprint

instance.pid = listener PID

process_state = alive

api_state = healthy

status = running

healthy = true
```

日志：

```text
gateway.process.safe_adopted
```

包含：

```text
instanceId
pid
port
reason=development_orphan_recovery
```

---

# 23. Safe Adoption 失败

只要一项不符合：

```text
ownership = conflict
```

返回：

```text
GATEWAY_PORT_OWNERSHIP_CONFLICT
```

禁止：

```text
Kill
Restart
Takeover
```

---

# 24. Health ≠ Ownership

必须增加回归测试，保证：

```text
GET /health → 200
```

但：

```text
Executable mismatch
```

时：

```text
ownership != adopted
```

这条是 v1.5.1 的安全底线。

---

# 25. Dev Reload Stability

目前：

```text
uvicorn --reload
```

会导致 Runtime application process 重启。

必须明确：

```text
reload
```

和：

```text
full Runtime shutdown
```

语义不同。

---

# 26. Shutdown Reason

增加 Runtime Shutdown Context：

```text
reload
normal_shutdown
process_termination
unknown
```

如果 Uvicorn 能可靠识别 reload：

```text
reload
```

时不要主动停止 Gateway。

然后新 worker：

```text
adopt
```

---

# 27. 如果无法可靠判断 Reload

优先策略：

> 不依赖 reload shutdown hook 判断。

直接依靠：

```text
Persistent Fingerprint
+
Startup Reconcile
+
Safe Adoption
```

实现稳定恢复。

这比猜 Uvicorn reload 原因可靠。

---

# 28. Gateway Shutdown Policy

Runtime **正式停止**：

```text
Ctrl+C
Windows Service Stop
Runtime API controlled shutdown
```

应：

```text
stop owned Gateways
```

---

Runtime **开发热重载**：

允许：

```text
Gateway 保持运行
```

由新 Runtime worker：

```text
ownership recovery
```

继续接管。

---

# 29. Orphan Prevention

虽然支持 Adoption，但仍应尽量减少 Orphan。

增加：

```text
GatewayProcessManager
```

记录：

```text
parent_runtime_pid
```

以及 Process Fingerprint。

---

# 30. Runtime 子进程监控

GatewayProcessManager 当前如果拥有：

```text
asyncio.subprocess.Process
```

应启动：

```text
process watcher
```

例如：

```python
async def _watch_process(instance_id, process):
    exit_code = await process.wait()
    ...
```

Gateway 自然退出后立即：

```text
process_state=exited
```

而不是等 5 秒 Health Worker。

---

# 31. Process Exit Event

记录：

```text
gateway.process.exited
```

包含：

```text
instanceId
pid
exitCode
expected
```

如果：

```text
desired=running
```

再交给 v1.5 Auto Recovery。

本 Hotfix 不重写 Crash Recovery。

---

# 32. 不重复启动 Gateway

v1.5.1 必须重点防止：

```text
Runtime reload
↓
old Gateway alive
↓
new Runtime immediately spawn second Gateway
```

启动前顺序强制：

```text
Ownership Reconcile
↓
Port Inspection
↓
Safe Adoption
↓
Only then Start
```

# 33. Start API 修正

调用：

```http
POST /instances/{id}/start
```

时：

不能直接：

```text

→ conflict
```

先执行：

```text
inspect existing process
```

如果属于可恢复 Runtime Gateway：

```text
adopt
```

然后返回：

```text
running
```

# 34. Restart API

`restart` 必须要求：

```text
ownership=owned/adopted
```

才允许：

```text
terminate
```

如果：

```text
ownership=unknown/foreign/conflict
```

返回：

```text
409 GATEWAY_NOT_OWNED
```

不得杀进程。

---

# 35. Stop API

同样：

```text

→ stop

foreign
→ 409

→ 409
```

# 36. Fingerprint 清理

以下情况清空 Fingerprint：

```text

owned Gateway exited

PID confirmed stale

RuntimeVersion removed

Instance deleted
```

---

# 37. Fingerprint 不应过早清理

以下情况不要清：

```text

temporary health failure

API authentication failure

temporary port query failure
```

否则会破坏 Ownership Recovery。

# 80. v1.5.1 五个硬验收指标

Cursor 完成后必须实际验证：

1. **`uvicorn --reload` 后，原 Runtime-owned Gateway 可以被新 Runtime worker 自动重新认领，不产生 `GATEWAY_PORT_OWNERSHIP_CONFLICT`。**
2. **Runtime restart 后，只要 Persistent Fingerprint 仍与 live PID/createTime/executable/port 匹配，就恢复 Ownership，不重复启动 Gateway。**
3. **Development orphan Gateway 只有满足严格 executable + command + profile + port + authenticated health 条件时才允许 Safe Adoption。**
4. **任意健康但无法证明属于 Runtime 的外部 Gateway 都不得被自动接管或终止。**
5. **整个 Hotfix 不修改 Chat / Task 执行逻辑；修复完成后它们只是因为默认 Instance 恢复 `executionEligible=true` 而自动恢复可用。**

**v1.5.1 的核心不是“绕过 `GATEWAY_PORT_OWNERSHIP_CONFLICT`”，而是让 Runtime 在重启、reload 和开发 orphan 场景下能够重新建立可验证的进程所有权，同时仍拒绝接管真正的外部 Gateway。**
