# 2. Hermes Agent Kanban 的真实定位

Hermes Kanban 不是普通前端 Task Board。

它本质上是：

> 多 Profile Agent 的持久化任务队列 + 状态机 + Dispatcher。

Hermes 官方当前定义中，Kanban 是 SQLite-backed durable board，不同 Profile/Worker 围绕共享任务协作；用户通过 `hermes kanban` 操作，Dispatcher 默认负责 reclaim、promote、claim 和启动对应 Profile。

因此：

```text
Kanban ≠ SMC UI Task List

Kanban =
Board
+
Task Graph
+
Agent Assignment
+
Workspace
+
Dispatcher
+
Worker Run
+
Comment
+
Event
```

Hermes Agent 当前还明确支持多 Board：

```text
default
project-a
project-b
...
```

每个 Board 都是独立 Queue，并且所有 CLI action 都支持：

```bash
hermes kanban --board <slug> ...
```

# 3. 不要与 SMC WorkTask 合并

当前 `smc-copilot` 已经存在：

```text
/api/v1/tasks
WorkTaskService
TaskEventService
```

并且 `/tasks` 当前本身就是：

```text
Legacy /api/v1/tasks
        ↓
WorkTaskService Compatibility Adapter
```

因此 Hermes Kanban 不允许映射为：

```text
Hermes KanbanTask
      ↓
SMC WorkTask
      ↓
Runtime DB
```

否则会产生：

```text
Hermes kanban.db        一套状态
Runtime work_tasks      一套状态

        ↓

Dual Source of Truth
```

最终会出现：

```text
Hermes = running
SMC = ready
```

这种不可接受的状态漂移。

### 正确关系

```text
WorkTask
   └── SMC 平台任务模型

KanbanTask
   └── Hermes Agent 原生任务模型
```

两者独立。

未来如需集成，只做：

```text
WorkTask
   └── externalRef
       = hermes-kanban://instance/board/task
```

不复制 Kanban 生命周期。

# 6. Runtime Transport 策略

建议不要把 Runtime 与某一种 Hermes Kanban transport 绑死。

定义：

```python
class HermesKanbanAdapter(Protocol):
    async def list_boards(...)
    async def list_tasks(...)
    async def get_task(...)
    async def create_task(...)
    async def execute_action(...)
    async def dispatch(...)
```

然后提供两个实现层次。

## P0：CLI Adapter

```text
HermesKanbanCliAdapter
```

Runtime 内执行：

```bash
hermes kanban --board xxx list --json
hermes kanban --board xxx show TASK --json
...
```

优势：

* 与当前 Hermes Desktop 行为一致；
* 不依赖 Dashboard Plugin；
* 当前 Hermes CLI 能力覆盖广；
* 最适合第一阶段快速迁移。

Hermes 官方当前 CLI 已提供 Board、Create、Assign、Link、Comment、Complete、Block、Schedule、Unblock、Archive、Dispatch、Specify、Decompose 等完整命令面。

## P1：Plugin API Adapter

后续增加：

```text
HermesKanbanPluginAdapter
```

Hermes Kanban 本身已经带 Dashboard Plugin，官方源码也将 `plugins/kanban/dashboard/` 列为 Kanban 组成部分。

历史 Kanban Gap Report 进一步记录其 Dashboard Plugin 暴露 REST 和实时 task events WebSocket。

因此未来 Runtime 可以：

```text
Plugin available
      ↓ yes
REST + events

      ↓ no
CLI Adapter
```

Desktop 无需知道使用哪一种 Transport。

# 7. 不允许 Runtime 直接修改 kanban.db

禁止：

```python
sqlite3.connect("~/.hermes/kanban.db")
UPDATE tasks SET status = ...
```

即使技术上能够实现，也不能采用。

原因：

```text
Hermes CLI / Plugin
    ↓
Dependency rules
State transition
Comments
Events
Dispatcher state
Workspace
Run state
```

这些行为属于 Hermes Agent。

直接操作数据库会绕过生命周期规则。

Runtime 是：

> Hermes Kanban Facade

而不是：

> Kanban Repository。

# 8. Board 必须显式 Scope

这是对原 Hermes Desktop 建议进行的一项重要修正。

当前 Desktop 点击 Board 时调用：

```text
kanbanSwitchBoard(slug)
```

最终执行：

```bash
hermes kanban boards switch xxx
```

当前 Hermes CLI 的 `boards switch` 会修改持久化 Current Board。

这适合单 CLI。

但对 Runtime 不够安全。

假设：

```text
Desktop Window A → board-a

Desktop Window B → board-b
```

如果都修改 Hermes Current Board：

```text
A switch board-a
B switch board-b

A 下一次请求
可能误操作 board-b
```

### SMC 改为

Desktop 保存：

```ts
selectedBoardSlug
```

每个 Runtime 请求显式携带：

```text
boardSlug
```

Runtime 执行：

```bash
hermes kanban --board project-a list
```

官方 CLI 已明确支持所有 action 使用 `--board`。

因此：

```text
Board UI Selection
≠
Hermes Global Current Board
```

只有真正需要改变 Hermes 默认 Board 时，才提供独立：

```text
Set as default
```

动作。

# 12. Drag & Drop 不能等同于 setStatus

当前 Hermes Desktop 已经意识到了这一点。

它不是：

```ts

    status: targetColumn
})
```

而是：

```text

→ complete

目标 Blocked
→ block

Blocked → Ready
→ unblock

Running → Ready
→ reclaim

Todo → Ready
→ promote

→ Scheduled
→ schedule
```

当前源码明确维护了这套 `dragAction()` 映射。

但 SMC 不建议继续让 Renderer 成为规则 Source of Truth。

# 13. 状态规则迁入 Runtime

定义：

```ts
type KanbanTaskAction =
  | "assign"
  | "complete"
  | "block"
  | "unblock"
  | "archive"
  | "reclaim"
  | "promote"
  | "schedule"
  | "specify"
  | "decompose"
  | "link"
  | "unlink";
```

Runtime Task DTO 推荐增加：

```ts
interface KanbanTask {
    ...
    allowedActions: KanbanTaskAction[];
}
```

Desktop：

```text
allowedActions.includes("complete")
      ↓
允许拖 Done
```

而不是自己推导 Hermes 状态机。

### 好处

Hermes 升级 transition：

```text
Runtime Adapter 修改一次
```

不用同步：

```text
Runtime
+
Desktop
+
Drag Logic
```

历史 Gap Report 也明确指出，Desktop 重复实现 transition rule 会存在和 Backend 漂移的问题。
