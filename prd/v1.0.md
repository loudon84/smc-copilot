# 2. 项目背景

当前 SMC Copilot 由两个独立仓库组成：

## 2.1 Desktop

`ai-os-desktop` 当前承担：

* Electron 桌面壳；
* Main / Preload / Renderer 分层；
* Hermes Agent 与 Runtime 连接；
* Chat、Profile、Workspace、Web Operator；
* Runtime 安装、启动、状态与日志管理；
* Windows、macOS、Linux 桌面构建。

Desktop 已有独立的 npm 构建、类型检查、Vitest、Playwright、Electron Builder 和 CI 脚本。其 `package.json` 中已经形成完整的 `lint → typecheck → test → build → e2e` 流程。

Electron Vite 和 Electron Builder 大量使用相对于 Desktop 项目根目录的路径，例如：

```text
src/preload/index.ts
src/renderer/src
resources/
build/
dist/
```

因此，迁移后所有 Desktop 命令必须以 `apps/desktop` 为工作目录执行，不能直接把原命令放在 Monorepo 根目录执行。

## 2.2 Runtime

`ai-os-serve` 当前承担：

* Hermes Agent 安装、升级、回滚；
* Runtime Instance 和 Gateway 管理；
* 本地鉴权和设备配对；
* Runtime Job 与 SSE；
* FastAPI Runtime API；
* SQLite、Alembic 和本地服务生命周期；
* Windows UserDaemon 与 Windows Service。

Runtime 当前使用 Python `>=3.12,<3.13`，依赖和测试体系由 `uv`、pytest、ruff 和 Alembic 管理。

FastAPI 已经设置应用名称、版本、路由和统一错误处理，具备直接导出 OpenAPI 的基础。

## 2.3 当前问题

两个仓库分离导致：

1. Desktop 和 Runtime API 修改不能形成原子提交。
2. Runtime DTO 与 Desktop TypeScript 类型存在重复定义。
3. API、SSE、错误码可能产生版本漂移。
4. 跨项目功能需要两个 PR 和两套 CI。
5. Cursor 需要重复读取两个仓库的架构文档。
6. E2E 无法在统一变更集内验证。
7. Desktop 安装包与 Runtime 制品版本兼容关系不够明确。
8. 发布时难以确定 Desktop 对应的 Runtime 最低版本。

# 3. 建设目标

## 3.1 总体目标

建设一个统一 Git 仓库：

```text
smc-copilot
```

同时保持：

```text
代码同仓
构建隔离
依赖隔离
契约统一
版本独立
制品独立
发布可追溯
```

## 3.2 功能目标

完成以下能力：

1. 将 Desktop 导入 `apps/desktop`。
2. 将 Runtime 导入 `services/runtime`。
3. 保留两个来源仓库的 Git 历史。
4. 使用 Nx 管理项目图、任务和 affected 范围。
5. 保留 Desktop 原有 npm 构建体系。
6. 保留 Runtime 原有 uv 构建体系。
7. 从 Runtime FastAPI 自动导出 OpenAPI。
8. 从 OpenAPI 自动生成 Desktop TypeScript Client。
9. 为 Job、Chat、Error 等非标准 HTTP 事件建立 JSON Schema。
10. 建立统一的 CI、契约漂移检查和跨项目测试。
11. 建立适合 Cursor Agent 的上下文隔离规则。
12. Desktop 和 Runtime 可以独立构建、测试、打包和发布。

---

# 4. 非目标

本版本不实施：

1. 不把 Runtime 改写为 Node.js。
2. 不把 Desktop 与 Runtime 编译成一个进程。
3. 不合并 npm 与 uv 依赖系统。
4. 不统一 Desktop 和 Runtime 的应用版本号。
5. 不重构现有 Desktop 功能。
6. 不重构 Runtime API 业务逻辑。
7. 不修改 Hermes Agent 安装目录和用户数据目录。
8. 不修改 Runtime 默认端口 `8765`。
9. 不修改 Hermes Gateway 默认端口。
10. 不将 FastAPI 服务生成器作为 Runtime 代码来源。
11. 不在本阶段重构现有认证和设备配对协议。
12. 不继续同时维护两个旧仓库。

# 5. 核心架构决策

## 5.1 采用 Repository Monorepo

Monorepo 只统一：

* Git 仓库；
* 项目关系；
* 契约；
* CI；
* 发布编排；
* Agent 上下文。

不强制统一：

* 开发语言；
* 依赖管理；
* 构建工具；
* 应用版本；
* 运行进程。

## 5.2 Desktop 保留独立 npm 项目

保留：

```text
apps/desktop/package.json
apps/desktop/package-lock.json
apps/desktop/node_modules
```

Desktop 安装：

```bash
cd apps/desktop
npm ci
```

禁止在 v1.0 中将 Desktop 改造成 npm workspace。

原因：

* Desktop 包含 Electron 原生模块 `better-sqlite3`；
* 当前 `postinstall` 会执行 native dependency rebuild；
* Electron Builder 对依赖目录和项目工作目录敏感；
* 首阶段迁移应避免改变 node_modules 提升策略。

## 5.3 Runtime 保留独立 uv 项目

保留：

```text
services/runtime/pyproject.toml
services/runtime/uv.lock
services/runtime/.venv
```

Runtime 安装：

```bash
cd services/runtime
uv sync --extra dev
```

## 5.4 Nx 只作为顶层任务编排器

Nx 负责：

* Project Graph；
* Target 编排；
* 缓存；
* affected 计算；
* 跨项目依赖顺序；
* CI 任务选择。

Nx 不负责：

* 安装 Desktop 业务依赖；
* 管理 Python package；
* 替代 npm；
* 替代 uv；
* 替代 Electron Builder；
* 替代 Alembic。

## 5.5 Runtime API 契约生成规则

契约治理采用：

```text
FastAPI 路由与 Pydantic Model
        ↓
自动导出 OpenAPI
        ↓
contracts/runtime-api/openapi.yaml
        ↓
生成 runtime-client-ts
        ↓
Desktop Main Process 使用
```

规则：

1. FastAPI 路由和 Pydantic Model 是接口编写来源。
2. `openapi.yaml` 是对外发布和消费的标准契约。
3. 禁止手工修改生成的 `openapi.yaml`。
4. 每次 Runtime API 变更必须重新生成契约。
5. CI 必须检查 Runtime 与 OpenAPI 是否漂移。
6. Desktop 禁止手工复制 Runtime Request/Response DTO。

Runtime 当前通过 `create_app()` 构建 FastAPI 实例，契约生成脚本应调用 `create_app().openapi()`，不能调用外层 ASGI CORS Wrapper。

## 5.6 SSE 和事件单独治理

OpenAPI 无法完整表达 SSE Event Union，因此增加：

```text
contracts/runtime-events/job-event.schema.json
contracts/runtime-events/chat-event.schema.json
contracts/runtime-events/error.schema.json
```

事件 Schema 同样从 Runtime Pydantic Model 生成，禁止手工维护两份定义。

# 7. 源码导入方案

## 7.1 导入原则

正式迁移必须保留 Git 历史。

禁止采用：

```text
git clone 两个仓库
→ 删除子目录 .git
→ 重新提交全部文件
```

该方式会丢失：

* 文件历史；
* blame；
* commit 关联；
* 回溯能力；
* 原 PR 对应关系。

正式迁移使用 `git subtree`，不使用 `--squash`。

## 7.2 初始化 Monorepo

```bash
mkdir smc-copilot
cd smc-copilot

git init -b main

echo "# SMC Copilot Monorepo" > README.md
git add README.md
git commit -m "chore: initialize smc-copilot monorepo"
```

## 7.3 导入 Desktop

```bash
git remote add desktop-source \
  https://github.com/loudon84/ai-os-desktop.git

git fetch desktop-source main

git subtree add \
  --prefix=apps/desktop \
  desktop-source main
```

禁止添加 `--squash`。

## 7.4 导入 Runtime

```bash
git remote add runtime-source \
  https://github.com/loudon84/ai-os-serve.git

git fetch runtime-source master

git subtree add \
  --prefix=services/runtime \
  runtime-source master
```

## 7.5 记录来源版本

新增：

```text
docs/architecture/source-imports.json
```

内容：

```json
{
  "desktop": {
    "repository": "https://github.com/loudon84/ai-os-desktop.git",
    "branch": "main",
    "commit": "<IMPORT_SHA>"
  },
  "runtime": {
    "repository": "https://github.com/loudon84/ai-os-serve.git",
    "branch": "master",
    "commit": "<IMPORT_SHA>"
  }
}
```

## 7.6 旧仓库处理

Monorepo 验收通过后：

1. 停止向旧仓库提交功能代码。
2. README 增加迁移通知。
3. 旧仓库设为只读或 Archive。
4. 保留至少一个版本周期用于历史查询。
5. 禁止 Monorepo 与旧仓库双向同步开发。

# 8. Nx 项目定义

## 8.1 项目清单

| Nx Project          | 路径                           | 类型                 |
| ------------------- | ---------------------------- | ------------------ |
| `desktop`           | `apps/desktop`               | Electron App       |
| `runtime`           | `services/runtime`           | FastAPI Service    |
| `contracts`         | `contracts`                  | Generated Contract |
| `runtime-client-ts` | `packages/runtime-client-ts` | TypeScript Library |
| `integration-e2e`   | `tools/integration` 或根测试目录   | Cross-project Test |

## 8.2 依赖关系

```text
runtime
   ↓ 生成
contracts
   ↓ 生成
runtime-client-ts
   ↓ 使用
desktop
```

Nx 依赖方向：

```text
contracts implicitDependencies → runtime
runtime-client-ts implicitDependencies → contracts
desktop implicitDependencies → runtime-client-ts
```

禁止形成：

```text
runtime → runtime-client-ts
contracts → desktop
runtime-client-ts → desktop
```

## 8.3 根 package.json

根项目只安装 Nx 和契约生成工具。

建议结构：

```json
{
  "name": "smc-copilot-monorepo",
  "private": true,
  "scripts": {
    "nx": "nx",
    "graph": "nx graph",
    "bootstrap": "nx run-many -t install",
    "check": "nx run-many -t lint,typecheck,test",
    "build": "nx run-many -t build",
    "affected:check": "nx affected -t lint,typecheck,test",
    "affected:build": "nx affected -t build",
    "dev:desktop": "nx run desktop:dev",
    "dev:runtime": "nx run runtime:dev",
    "contracts:generate": "nx run contracts:generate",
    "contracts:check": "nx run contracts:check",
    "client:generate": "nx run runtime-client-ts:generate",
    "integration:test": "nx run integration-e2e:test"
  },
  "devDependencies": {
    "nx": "<locked-version>",
    "@nx/workspace": "<same-version>"
  }
}
```

实施时必须将 Nx 锁定到同一个明确版本，并提交根 `package-lock.json`。

## 8.4 nx.json

核心要求：

```json
{
  "$schema": "./node_modules/nx/schemas/nx-schema.json",
  "defaultBase": "main",
  "namedInputs": {
    "default": [
      "{projectRoot}/**/*",
      "sharedGlobals"
    ],
    "production": [
      "default",
      "!{projectRoot}/**/*.test.*",
      "!{projectRoot}/tests/**/*"
    ],
    "sharedGlobals": [
      "{workspaceRoot}/contracts/**/*",
      "{workspaceRoot}/nx.json"
    ]
  },
  "targetDefaults": {
    "build": {
      "cache": true,
      "dependsOn": ["^build"]
    },
    "test": {
      "cache": true
    },
    "lint": {
      "cache": true
    },
    "typecheck": {
      "cache": true
    }
  }
}
```

# 9. Desktop Nx Target

新增：

```text
apps/desktop/project.json
```

必须包含：

| Target          | 命令                          |
| --------------- | --------------------------- |
| `install`       | `npm ci`                    |
| `dev`           | `npm run dev`               |
| `lint`          | `npm run lint`              |
| `typecheck`     | `npm run typecheck`         |
| `test`          | `npm test`                  |
| `test-e2e`      | `npm run test:e2e:electron` |
| `build`         | `npm run build`             |
| `package-win`   | `npm run build:win`         |
| `package-mac`   | `npm run build:mac`         |
| `package-linux` | `npm run build:linux`       |

所有 Target 必须设置：

```json
{
  "options": {
    "cwd": "apps/desktop"
  }
}
```

不得从 Monorepo 根目录直接执行：

```bash
electron-vite build
electron-builder
node scripts/dev.cjs
```

原因是当前 Electron Vite 通过 `resolve('src/...')` 解析入口，Electron Builder 也以当前项目目录解析 `build`、`resources` 和 `dist`。

## 9.1 Desktop 原脚本处理

默认不修改：

```text
apps/desktop/package.json scripts
```

根 Nx 只调用原脚本。

只有以下情况允许修改：

* 脚本硬编码旧仓库绝对路径；
* 脚本假定 Git Root 等于 Desktop Root；
* 脚本调用 `git rev-parse --show-toplevel` 后拼接 Desktop 文件；
* 脚本需要读取 Monorepo 的 contracts；
* 脚本需要定位 `packages/runtime-client-ts`。

```text

```

| Target            | 命令                                                                            |
| ----------------- | ----------------------------------------------------------------------------- |

| `migrate`         | `uv run alembic upgrade head`                                                 |

| `format-check`    | `uv run ruff format --check .`                                                |
| `test`            | `uv run pytest`                                                               |
| `build`           | `uv build`                                                                    |
| `smoke`           | 执行 Runtime smoke test                                                         |
| `package-windows` | 执行 Windows Runtime Installer 构建                                               |

所有命令必须设置：

```json
{
  "options": {
    "cwd": "services/runtime"
  }
}
```

## 10.1 Runtime 脚本路径改造

当前 Windows 安装脚本默认：

```powershell
$RepoRoot = $PSScriptRoot + "\.."
```

该逻辑迁移后仍可正确解析到：

```text
smc-copilot/services/runtime
```

但脚本中的以下提示和约束必须更新：

```text
请将 copilot-serve clone 到 D:\Programs\copilot-serve
```

修改为：

```text
RuntimeRoot 必须位于允许的程序目录下。
Monorepo 开发态路径允许：
D:\Programs\smc-copilot\services\runtime
```

当前安装脚本会切换到 `$RepoRoot` 并从该目录读取 `.env`、执行 bootstrap 和 uv，因此 Nx 不得把 `$RepoRoot` 设置为 Monorepo 根目录。

## 10.2 Runtime Root 与 Monorepo Root 区分

定义：

```text
MONOREPO_ROOT = smc-copilot/
RUNTIME_SOURCE_ROOT = smc-copilot/services/runtime/
DESKTOP_SOURCE_ROOT = smc-copilot/apps/desktop/
```

所有 Runtime 安装脚本继续以 `RUNTIME_SOURCE_ROOT` 为代码根。

# 11. Portal Root 边界

Desktop 当前的 `COPILOT_PORTAL_ROOT` 用于定位另一个包含：

```text
package.json
backend/
frontend/
```

的 Portal Monorepo。

因此：

1. 禁止将新的 `smc-copilot` 根目录写入 `COPILOT_PORTAL_ROOT`。
2. 禁止修改 `isPortalMonorepoRoot()` 以适配本项目。
3. SMC Copilot Monorepo 与 Portal Monorepo 是两个不同概念。
4. 如需增加本仓库根路径，使用新变量：

```text
SMC_COPILOT_MONOREPO_ROOT
```

开发环境可由 Nx 注入：

```text
SMC_COPILOT_MONOREPO_ROOT=<workspaceRoot>
```

生产安装包不得依赖源码 Monorepo 路径。

# 12. Runtime API 契约

## 12.1 OpenAPI 导出

新增：

```text
tools/contract-generate/export_openapi.py
```

执行流程：

```python
将 services/runtime/src 加入 sys.path
→ import app.create_app
→ fastapi_app = create_app()
→ schema = fastapi_app.openapi()
→ 规范化排序
→ 写入 contracts/runtime-api/openapi.yaml
```

生成结果必须稳定：

* 固定字段排序；
* 禁止时间戳；
* 禁止本机绝对路径；
* 禁止随机 ID；
* 同一源码连续生成结果必须完全一致。

## 12.2 错误 Schema

Runtime 当前统一错误格式为：

```json
{
  "error": {
    "code": "string",
    "message": "string",
    "details": {},
    "requestId": "string"
  }
}
```

该结构应导出为：

```text
contracts/runtime-events/error.schema.json
```

不得在 Desktop 重新手写不同版本。

## 12.3 契约漂移检查

新增：

```bash
npm run contracts:check
```

检查逻辑：

```text
临时重新生成 OpenAPI 和 JSON Schema
→ 与 Git 中已提交文件比较
→ 有差异则退出码 1
```

CI 错误提示必须明确：

```text
Runtime contract drift detected.
Run: npm run contracts:generate
Commit generated contract changes.
```

## 12.4 Breaking Change 检查

以下变化视为 Breaking Change：

* 删除 endpoint；
* 修改 HTTP method；
* 删除 response 字段；
* 将可选字段改为必填；
* 缩小 enum；
* 修改字段类型；
* 修改鉴权方式；
* 删除 SSE event type；
* 修改错误 envelope 根结构。

发生 Breaking Change 时必须：

1. 提升 `contracts/version.json` 主版本。
2. 增加 ADR。
3. 声明 Desktop 最低兼容版本。
4. 补充 Runtime compatibility test。

# 13. TypeScript Runtime Client

## 13.1 目录

```text
packages/runtime-client-ts/
├─ src/
│  ├─ generated/
│  ├─ client/
│  │  ├─ create-runtime-client.ts
│  │  ├─ auth-provider.ts

│  │  └─ sse-client.ts
│  └─ index.ts
├─ package.json
├─ tsconfig.json
├─ project.json
└─ README.md
```

## 13.2 代码边界

```text
src/generated/
```

只能由 OpenAPI Generator 写入。

禁止：

* 手工修改 generated 文件；
* 在 generated 文件中写业务逻辑；
* Desktop 直接 import generated 深层路径。

Desktop 只允许：

```typescript
import {
  createRuntimeClient,
  RuntimeApiError,
  type RuntimeStatus,
} from "@smc/runtime-client";
```

## 13.3 Desktop 接入位置

生成 Client 只能在 Electron Main Process 或可信本地服务层创建。

禁止在 Renderer 创建带 Runtime Token 的 Client。

现有：

```text
src/shared/copilot-serve/copilot-serve-contract.ts
```

继续保留，其职责是 Electron Main / Preload / Renderer 之间的本地进程控制契约，包括：

* start；
* stop；
* restart；
* status；
* deploy；
* logs。

它不是 Runtime HTTP API Contract，不能直接删除。

现有 `copilot-serve-api.ts` 继续作为 Preload IPC wrapper，不改为直接 HTTP 调用。

## 13.4 TypeScript 路径接入

Desktop 增加：

```json
{
  "paths": {
    "@smc/runtime-client": [
      "../../packages/runtime-client-ts/src/index.ts"
    ]
  }
}
```

同时在 `electron.vite.config.ts` 为需要使用 Client 的进程配置 alias。

首阶段建议只允许 Main Process 引用：

```text
apps/desktop/src/main/**
```

Renderer 和 Preload 禁止直接引用生成 Client。

# 14. Contract Version

`contracts/version.json` 只管理契约版本，不管理应用版本。

示例：

```json
{
  "runtimeApi": "1.3.0",
  "runtimeEvents": "1.0.0",
  "compatibility": {
    "minimumDesktopVersion": "0.1.9",
    "minimumRuntimeVersion": "1.6.0"
  }
}
```

版本来源：

| 内容              | 来源                                |
| --------------- | --------------------------------- |
| Desktop 版本      | `apps/desktop/package.json`       |
| Runtime 版本      | `services/runtime/pyproject.toml` |
| Runtime API 版本  | `contracts/version.json`          |
| Event Schema 版本 | `contracts/version.json`          |

禁止设置单一 Monorepo 产品版本覆盖全部子项目。

## 15.1 根 AGENTS.md

```markdown
# SMC Copilot Repository Routing
```

### repository-routing.mdc

### desktop-boundary.mdc

Glob：

```text
apps/desktop/**
```

### runtime-boundary.mdc


规则：

* Python 版本固定为 3.12；
* 使用 uv；
* 数据库变化必须有 Alembic migration；
* API 变化必须生成契约；
* SSE 变化必须生成事件 Schema。

### contract-boundary.mdc

Glob：

```text
contracts/**
packages/runtime-client-ts/**
tools/contract-generate/**
```

规则：

* generated 文件禁止手工修改；
* 先生成 OpenAPI，再生成 TypeScript Client；
* breaking change 必须升级契约主版本。

# 22. 回滚方案

## 22.1 Phase 1—2 回滚

如果源码导入后独立构建无法恢复：

1. 删除 Monorepo 迁移分支。
2. 继续使用旧 Desktop、Runtime 仓库。
3. 不影响旧仓库提交历史和发布。

## 22.2 Contract 回滚

如果生成 Client 无法稳定使用：

1. 保留 OpenAPI 和 Schema 生成。
2. Desktop 暂时继续使用原手写 Client。
3. 不删除现有 DTO。
4. 将 TS Client 接入延后到后续版本。

## 22.3 发布回滚

Desktop 和 Runtime 独立回滚：

```text
Desktop 回滚不要求 Runtime 同时回滚；
Runtime 回滚必须满足 contracts/version.json 兼容矩阵。
```
