# 2. 问题背景

v1.3.1 已完成 Desktop 启动链从：

```text
Desktop
→ Hermes Gateway :8642
```

向：

```text
Desktop
→ Runtime Service :8765
```

的迁移。

当前启动：

```bash
npm run dev:runtime
npm run dev:desktop
```

Desktop 页面能够正确显示：

```text
Endpoint
http://127.0.0.1:8765

Runtime
1.6.0 / API 2.0

Desktop API
3.0
```

随后进入：

```text
PAIRING_REQUIRED
```

因此当前问题已经不是 Runtime 网络不可达。

Desktop 已成功访问 Runtime，并成功取得 Runtime Status、Capabilities 和 Compatibility；当前阻塞点是 **Desktop 尚无有效 Device Token**。当前 Runtime Connection Manager 本身也是在读取 Runtime 状态和能力之后才判断 `isPairedSync()`。

当前实际链路：

```text
Desktop
   ↓
Runtime :8765                         ✅
   ↓
GET Runtime Status                   ✅
   ↓
GET Runtime Capabilities             ✅
   ↓
GET Runtime Compatibility            ✅
   ↓
Device Token
   ↓
不存在 / 无效                         ❌
   ↓
PAIRING_REQUIRED
   ↓
Pairing Screen
```

v1.3.2 要解决：

```text
PAIRING_REQUIRED
       ↓
Pair & Continue
       ↓
Device Token
       ↓
Runtime Handshake
       ↓
READY
       ↓
Main
```

# 3. 当前实现基础

本 Hotfix 不重新建设 Pairing Backend。

Runtime 已提供：

```http
POST /api/v1/pairings/start

POST /api/v1/pairings/{pairingId}/confirm

GET /api/v1/devices

DELETE /api/v1/devices/{deviceId}
```

并且 Pairing API 只允许 loopback 请求。

Runtime Pairing Service 已实现：

```text
Challenge generation
Challenge hash
5 分钟有效期
Pairing status
Device creation
Device token creation
Token hash
Device audit
Device revoke
```

Desktop Main 也已经实现：

```text
startPairing()
confirmPairing()
saveDeviceToken()
```

并且 Challenge 被保存在 Main Process 内存中，不暴露给 Renderer。

Device Token 已支持：

```text
keytar
↓ fallback
Electron safeStorage
↓ fallback
memory
```

持久化。

Runtime HTTP Client 在后续请求中会自动注入：

```http
Authorization: Bearer <deviceToken>
```

因此：

> v1.3.2 的核心不是新增 Pairing Protocol，而是将已有能力组合成完整的 Desktop Startup Authorization Transaction。

# 4. 当前问题点

## 4.1 Pairing 只有能力，没有完整产品闭环

目前已经存在：

```text
startPairing
confirmPairing
saveDeviceToken
runRuntimeHandshake
```

但是 UI 仍将：

```text
Start Pairing
```

表现为一个孤立操作。

正确逻辑应该是：

```text
Start
+
Confirm
+
Persist Token
+
Handshake
+
Navigate
```

一次完成。

---

# 4.2 `PAIRING_REQUIRED` 被错误表现为 Runtime 故障

当前页面同时显示：

```text
Device pairing required (PAIRING_REQUIRED)

Retry Connection
Run Doctor
Open Diagnostics
Start Pairing
```

这在产品语义上是错误的。

实际上此时状态为：

```text
Runtime Network        Healthy
Runtime Service        Healthy
Runtime Compatibility  Passed
Authentication         Pairing Required
```

因此：

```text
PAIRING_REQUIRED ≠ Connection Failure
PAIRING_REQUIRED ≠ Runtime Degraded
PAIRING_REQUIRED ≠ Runtime Recovery
```

---

# 4.3 Renderer 不应该编排 Pairing Protocol

如果 Renderer 自己执行：

```text
startPairing
→ confirmPairing
→ retry
```

Renderer 将逐渐理解：

```text
pairingId
challenge
Device Token
Runtime authentication
```

这违反当前：

```text
Renderer
→ semantic IPC
→ Main
→ Runtime Protocol
```

边界。

Pairing Transaction 应归 Electron Main Process 所有。

---

# 4.4 Pairing 后必须立即重新 Handshake

仅保存 Device Token 不够。

必须：

```text
saveDeviceToken
      ↓
runRuntimeHandshake
      ↓
GET Runtime Status with Bearer Token
      ↓
READY
```

否则 Renderer 仍可能停留：

```text
PAIRING_REQUIRED
```

直到用户手工 Retry 或重启 Desktop。

---

# 4.5 Device Token 必须跨 Desktop Restart 保留

第一次：

```text
Pair
→ Device Token
→ READY
```

第二次启动必须：

```text
hydrateRuntimeAuthStore()
→ token found
→ READY
→ Main
```

不得：

```text
Desktop restart
→ PairingRequired again
```

当前 Auth Store 已具备该基础能力。

```text

```


```text

```

---

# 7.2 PairAndConnectResult

新增共享 Contract：

```ts
export interface RuntimePairAndConnectResult {
  ok: boolean;

  state: RuntimeConnectionState;

  deviceId: string | null;

  error: {
    code: string;
    message: string;
    retryable: boolean;
  } | null;
}
```

禁止返回：

```text
challenge
deviceToken
```

给 Renderer。

---

# 7.3 Main 执行流程

新增：

```ts
export async function pairAndConnect():
  Promise<RuntimePairAndConnectResult>
```

逻辑：

```text
1. 检查当前 RuntimeConnectionState

2. 必须属于 PairingRequired
        ↓
3. POST /pairings/start
        ↓
4. Main 保存 challenge
        ↓
5. POST /pairings/{id}/confirm
        ↓
6. Runtime 返回 deviceToken
        ↓
7. saveDeviceToken()
        ↓
8. runRuntimeHandshake()
        ↓
9. state == Ready
        ↓
10. 返回成功
```

---

# 7.4 伪代码

```ts
export async function pairAndConnect():
  Promise<RuntimePairAndConnectResult> {

  const current = getRuntimeConnectionState();

  if (
    current.state !== "PairingRequired" &&
    current.state !== "Ready"
  ) {
    return {
      ok: false,
      state: current,
      deviceId: null,
      error: {
        code: "PAIRING_NOT_ALLOWED",
        message:
          `Pairing cannot start from ${current.state}`,
        retryable: true,
      },
    };
  }

  if (current.state === "Ready") {
    return {
      ok: true,
      state: current,
      deviceId: getDeviceMetaSync()?.deviceId ?? null,
      error: null,
    };
  }

  const start = await startPairing();

  if (!start.pairingId) {
    return failure(...);
  }

  const confirmed =
    await confirmPairing(start.pairingId);

  if (!confirmed.ok) {
    return failure(...);
  }

  const state =
    await runRuntimeHandshake();

  return {
    ok: state.state === "Ready",
    state,
    deviceId: confirmed.deviceId,
    error:
      state.state === "Ready"
        ? null
        : {
            code:
              state.lastErrorCode ??
              "PAIRING_HANDSHAKE_FAILED",
            message:
              state.lastError ??
              "Runtime did not enter Ready state",
            retryable: true,
          },
  };
}
```
