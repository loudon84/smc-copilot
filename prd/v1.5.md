# 2. 版本背景

v1.4.1 已建立以下基础链路：

```text
Local Hermes
    ↓
DevHermesRegistrationService
    ↓
RuntimeVersion
    ↓
HermesInstance
    ↓
InstanceGatewayService
    ↓
GatewayProcessManager
    ↓
hermes gateway run --external-supervisor
    ↓
Hermes Gateway :8642+
```

当前开发模式已经可以通过：

```text
HERMES_DEV_EXECUTABLE
        ↓
或
shutil.which("hermes")
        ↓
hermes --version
        ↓
RuntimeVersionService.register_external()
        ↓
InstanceService.ensure_default()
```

将本地已有 Hermes 注册到 Runtime。

`RuntimeVersionService` 已支持：

```text
channel = development
source = external-dev
managed = false
status = active
```

并维护 active RuntimeVersion。

`InstanceService.ensure_default()` 已能够建立默认受管 Instance：

```text
default
profile = default
gatewayPort = 8642
autoStart = true
```

并绑定 Active RuntimeVersion。

# 4. 当前核心问题

v1.5 不重新建设 Gateway，而是解决现有 Supervisor 的五个关键缺口。

## 4.1 Hermes 状态概念混合

当前系统实际存在：

```text
Hermes executable
Hermes Instance
Gateway process
Gateway HTTP API
```

四种不同状态。

但 Runtime Readiness 最终压缩成：

```text
hermes
instance
gateway
```

导致：

```text
Hermes 可执行文件存在
```

容易与：

```text
Hermes Gateway 已连接
```

混淆。

---

# 4.2 Gateway Health 判定过宽

当前 `HermesGatewayClient.health_check()`：

首先：

```http
GET /health
```

失败后 fallback：

```http
GET /v1/models
```

但 fallback 当前：

```python
if resp.status_code < 500:
    return True
```

意味着：

```text
200 → healthy
401 → healthy
403 → healthy
404 → healthy
429 → healthy
```

均可能得到：

```text
healthy = true
```

这是错误语义。

例如：

```text
API_SERVER_KEY 不匹配

Gateway Process       Running
Port                  Listening
HTTP                  Reachable
Authentication        Failed

当前结果：
healthy = true
```

最终会产生：

```text
Runtime 显示 Ready
Chat / Task 实际全部 401
```

---

# 4.3 Runtime 只在部分操作中主动检测 Gateway

当前真正的 Gateway 检测发生于：

```text
start_instance()
refresh_instance_status()
reconcile_instances_on_boot()
```

其中 `GET /instances/{id}/health` 才会主动：

```text
PID
+
Gateway HTTP
+
DB Update
```

如果 Gateway 在 Runtime 正常运行期间突然 Crash：

```text
DB:
status=running
healthy=true

实际:
Gateway 已退出
```

直到下一次主动 Refresh，DB 可能继续保留旧状态。

---

# 4.4 PID Ownership 不够严格

Runtime 重启 Reconcile 当前会依赖：

```text
stored PID
+
is_pid_alive(pid)
```

随后如果 Gateway health 失败，存在 terminate PID 的路径。

但 OS 可能发生 PID reuse：

```text
原 Gateway PID = 1234
      ↓
Gateway / Runtime 异常退出
      ↓
PID 1234 被新程序复用
```

Runtime 如果只检测：

```text
pid_exists(1234)
```

不能证明：

> PID 1234 仍属于这个 Hermes Gateway。

---

# 4.5 Multi-instance Readiness 判断不正确

当前：

```python
select(HermesInstance).limit(1)
```

取数据库第一条 Instance，并同时作为：

```text
defaultInstance
instance
```

判断。

例如：

```text
finance    stopped
default    running / healthy
```

如果第一条刚好是 finance：

```text
execution.ready = false
```

即使默认 Hermes 完全健康。

这无法支持后续：

```text
default
finance
sales
coding
```

多 Instance 架构。

# 15. Ownership 判断

Runtime 只有同时满足：

```text
PID alive

AND

create_time matches

AND

PID listens on expected port

AND

process executable matches expected Hermes
```

才能：

```text
ownership = owned
```

否则：

```text
ownership = foreign / stale
```

---

# 16. Runtime 杀进程安全规则

只有：

```text
ownership == owned
```

允许：

```text
terminate
kill
restart
```

如果：

```text
PID mismatch
createTime mismatch
port owned by other PID
executable mismatch
```

必须：

```text
DO NOT KILL
```

状态：

```text
process_state = foreign
status = error

errorCode =
GATEWAY_PROCESS_OWNERSHIP_CONFLICT
```

# 28. Boot Reconcile 决策矩阵

### Case A

```text
desired=running
process owned
API healthy
```

：

```text
adopt existing process
observed=running/healthy
```

不重新启动。

---

### Case B

```text
desired=running
process missing
port free
```

：

```text
start Instance
```

---

### Case C

```text
desired=running
stored PID stale
port free
```

：

```text
clear stale PID
start Instance
```

不 Kill stale PID。

---

### Case D

```text
desired=running
port occupied by foreign process
```

：

```text
ERROR
GATEWAY_PORT_OWNERSHIP_CONFLICT
```

不 Kill。

---

### Case E

```text

API unauthorized
```

```text
ERROR
GATEWAY_AUTH_FAILED
```

禁止自动认为 Healthy。



# 96. v1.5 七个硬性验收指标

Cursor 实施完成后必须实际验证：

1. **Gateway 返回 401/403 时，Runtime 必须显示 Authentication Failed，而不是 Healthy。**
2. **Gateway 进程退出后，无需 Desktop Refresh，Runtime 5 秒级自动发现。**
3. **PID 被 OS 复用时，Runtime 不得误杀新进程。**
4. **8642 被未知进程占用时，Runtime 报 Port Ownership Conflict，不自动 Kill。**
5. **default Instance Healthy 时，其它 Instance Error 不得导致默认 Chat 整体不可用。**
6. **Gateway Crash 后按 Restart Budget 自动恢复；进入 Crash Loop 后停止自动重启。**
7. **Desktop 全程只访问 Runtime `:8765`，Gateway `:8642+` 的进程、端口、鉴权和健康状态全部由 Runtime 判断。**
