# Hermes Desktop 报告预览、下载与 Agent Output 管理 PRD

**版本：v1.1.1**
**目标项目：** `hermes-desktop`
**适用模块：** Chat、Session Files、File Preview、Agent Output
**实施环境：** Cursor
**状态：** 待开发

---

## 1. 项目背景

当前 Hermes Desktop 已能够通过 SSE 接收 Hermes Agent 输出，并在 Chat 消息区渲染 Markdown 报告。

现有结果表现为：

```text
Hermes Agent
  → 返回 Markdown 文本
  → Assistant Message
  → Chat 页面渲染
```

但未形成文件闭环：

```text
Assistant Message
  → 创建 Markdown 文档
  → 注册文件
  → 关联当前 Session
  → Agent Output 展示
  → 文件预览
  → 另存为
```

当前界面存在以下问题：

1. 已生成的报告只能在消息气泡中阅读。
2. 无法在独立预览面板中查看完整文档。
3. 无法保存或下载为 `.md` 文件。
4. Session Files 的 `Agent output` 仍显示无文件。
5. 重启应用后，报告仍只是历史消息，不是可管理文件。
6. Hermes 真正创建文件时，Desktop 缺少结构化文件注册机制。

根本原因是：**报告内容仍属于 Assistant Message，没有转换为 ManagedFile，也没有创建 FileAssociation。**

Hermes Desktop 的 Renderer 不具备直接文件系统访问权限，新增能力必须遵循：

```text
Renderer
  → Preload
  → IPC
  → Main Process
  → Profile 文件目录 / SQLite
```

该分层是 Hermes Desktop 的既有安全边界。

## 2. 产品定位

本版本建设统一的：

```text
Report Output Pipeline
```

负责将 Hermes 输出的报告从消息内容转化为可预览、可保存、可恢复、可管理的文档对象。

系统同时支持两类输出。

### 2.1 消息型报告

Hermes 只返回 Markdown 内容，没有创建物理文件：

```text
Assistant Markdown Message
  → 文档预览
  → 创建 .md
  → 注册 Agent Output
  → 另存为
```

这是本版本的 P0 范围。

### 2.2 文件型报告

Hermes 通过工具在 Workspace 中创建真实文件：

```text
Hermes File Tool
  → 创建 report.md
  → 上报 Artifact
  → Desktop 校验路径
  → 注册 ManagedFile
  → Agent Output
```

这是本版本的 P1 范围。

两条路径最终统一进入：

```text
ManagedFile
+
FileAssociation(role = "agent-output")
```

## 3. 建设目标

### 3.1 核心目标

完成以下用户闭环：

```text
查看报告消息
  → 打开文档预览
  → 保存为 Markdown
  → 出现在 Agent Output
  → 再次预览
  → 另存为指定位置
  → 重启后继续访问
```

### 3.2 业务目标

1. 报告生成结果不再只依赖消息气泡。
2. 文档文件与 Session、Message、Profile 建立明确关联。
3. 文档预览与文件创建解耦。
4. 支持消息转文件和现有文件注册两种方式。
5. 后续 PDF、DOCX、HTML 等报告格式可复用同一文件模型。
6. 为 Hermes Artifact 事件预留标准接口。

---

## 4. 非目标

本版本不实施：

* 不修改 Hermes Agent 核心对话循环。
* 不替换现有 Chat SSE。
* 不重构整个文件管理平台。
* 不实现 DOCX、PDF 导出。
* 不实现在线文档编辑器。
* 不自动解析任意文本中的本地路径。
* 不扫描磁盘查找 Hermes 生成文件。
* 不删除旧 Attachment 数据模型。
* 不删除现有图片附件数据库。
* 不实现云端文件同步。
* 不实现文件版本协同编辑。

## 5. 产品原则

### 5.1 消息和文件是不同对象

```text
Assistant Message
  ≠
ManagedFile
```

Assistant Message 是对话历史。

ManagedFile 是可操作、可关联、可持久化的文件对象。

### 5.2 预览不依赖文件创建

用户点击“文档预览”时，系统可直接使用消息正文进行预览，无需先写入磁盘。

### 5.3 下载统一使用另存为

Electron Desktop 中的“下载”统一实现为：

```text
Electron dialog.showSaveDialog
  → Main Process 写入目标路径
```

禁止使用浏览器 `<a download>` 作为主要实现。

### 5.4 Profile 强隔离

所有报告文件必须存放在当前 Profile 目录。

不同 Profile 不得互相查询或打开文件。

### 5.5 文件注册必须可信

只有以下来源可以注册 Agent Output：

1. 用户明确执行“保存为文档”。
2. 已知文件工具返回的结构化结果。
3. Hermes Artifact 结构化事件。
4. 已授权 Workspace 内的真实文件。

不得根据普通 Assistant 文本中的路径自动注册文件。

## 6. 用户场景

### 场景一：预览当前报告

用户在 Chat 中收到完整客户画像报告。

操作：

```text
点击“文档预览”
```

结果：

* 右侧打开 Markdown 文档预览。
* 报告内容完整显示。
* 原消息不发生变化。
* 不创建物理文件。

### 场景二：保存为 Markdown

用户点击：

```text
保存为 .md
```

系统执行：

```text
消息正文
  → 写入 Profile 受管目录
  → 创建 ManagedFile
  → 创建 FileAssociation
  → 打开系统另存为窗口
  → Agent Output 刷新
```

### 场景三：加入会话文件

用户点击：

```text
加入会话文件
```

系统创建受管文件并显示在：

```text
Session Files
  → Agent output
```

不强制打开另存为窗口。

### 场景四：重启后继续访问

用户重启 Hermes Desktop 并恢复原 Session。

结果：

* Agent Output 仍显示已生成报告。
* 点击后仍能预览。
* 可重新执行另存为。
* 原消息与文件关联不丢失。

### 场景五：Hermes 创建真实文件

Hermes 使用文件工具创建：

```text
客户画像报告.md
```

系统收到结构化 Artifact 事件后：

* 校验文件路径。
* 注册 ManagedFile。
* 关联当前 Session 和 Message。
* 自动显示在 Agent Output。
* 不要求用户再次从消息创建文件。

# 7.1 Assistant 文档识别

系统需要判断某条 Assistant Message 是否适合作为文档处理。

新增：

```text
document-message-utils.ts
```

建议规则：

```ts
export function isDocumentLikeMessage(
  content: string,
): boolean {
  const text = content.trim();

  if (text.length < 300) {
    return false;
  }

  const hasHeading = /^#{1,6}\s+/m.test(text);
  const hasMarkdownTable =
    /\|.+\|[\r\n]+\|[-:\s|]+\|/.test(text);
  const paragraphCount =
    text.split(/\n\s*\n/).filter(Boolean).length;

  return (
    hasHeading ||
    hasMarkdownTable ||
    paragraphCount >= 4
  );
}
```

该逻辑只控制操作按钮是否显示。

不得：

* 自动写文件。
* 自动生成 Agent Output。
* 自动判断敏感文件名。
* 自动修改消息内容。

# 7.4 从消息创建文件

新增 IPC：

```text
files:create-from-message
```

共享契约：

```text
src/shared/files/message-document.ts
```

```ts
export interface CreateFileFromMessageInput {
  profile?: string;
  sessionId: string;
  messageId: string;

  title: string;
  content: string;

  extension: "md" | "txt";
}

export interface CreateFileFromMessageResult {
  file: ManagedFile;
  association: FileAssociation;
  alreadyExisted: boolean;
}
```

行为要求：

1. 校验 Session ID、Message ID 和内容。
2. 清洗文件标题。
3. 写入当前 Profile 的受管目录。
4. 不覆盖同名文件。
5. 创建 ManagedFile。
6. 创建 FileAssociation。
7. 返回 `fileId`。
8. 通知 Renderer 刷新。

## 7.5 文件存储目录

物理文件存储：

```text
<profileHome>/
└─ desktop/
   └─ files/
      └─ generated/
         └─ <sessionId>/
            ├─ 客户画像报告.md
            ├─ 客户画像报告 (1).md
            └─ 客户画像报告 (2).md
```

禁止直接硬编码：

```text

```

Hermes Desktop 已要求所有 Profile 文件系统访问经过统一 Profile 根目录，避免破坏多 Profile 隔离。

# 7.6 文件名生成

新增：

```text
src/main/files/agent-output/
└─ generated-file-name.ts
```

```ts
export function sanitizeGeneratedFileName(
  title: string,
): string {
  const cleaned = title
    .normalize("NFKC")
    .replace(/[<>:"/\\|?*\u0000-\u001F]/g, "-")
    .replace(/\s+/g, " ")
    .replace(/\.+$/g, "")
    .trim()
    .slice(0, 80);

  return cleaned || "generated-report";
}
```

文件名生成：

```ts
export function createGeneratedFileName(
  title: string,
  extension: "md" | "txt",
): string {
  return `${sanitizeGeneratedFileName(title)}.${extension}`;
}
```

标题来源优先级：

```text
1. 消息明确的报告标题
2. Assistant Message 第一行 Markdown Heading
3. Session 标题
4. generated-report
```

禁止让 LLM 输出的任意路径直接作为保存位置。

## 11. 文件型报告流程

P1 增加 Hermes Artifact 事件。

### 11.1 SSE 事件

新增：

```text

```

契约：

```ts
export interface ChatArtifactEvent {
  artifactId: string;

  type: "file";
  role: "agent-output";

  name: string;
  mime: string;
  path: string;

  sessionId?: string;
  messageId?: string;

  operation:
    | "created"
    | "updated";

  metadata?: {
    title?: string;
    description?: string;
    toolName?: string;
  };
}
```

### 11.2 处理流程

```text
收到 chat.artifact
→ 验证事件 schema
→ 校验真实文件路径
→ 检查文件是否存在
→ 检查是否位于 Workspace/授权目录
→ 读取 stat
→ 识别 MIME
→ registerExistingFile
→ 创建 agent-output 关联
→ 刷新 Agent Output
```

Hermes Agent 已提供工具和生命周期 Hook 扩展点，后续可通过 `post_tool_call` 等 Hook 将文件产物转换为结构化事件，避免 Desktop 解析自然语言路径。

## 13. 错误处理

统一错误：

```ts
export type AgentOutputErrorCode =
  | "INVALID_MESSAGE_CONTENT"
  | "INVALID_FILE_TITLE"
  | "GENERATED_DIRECTORY_FAILED"
  | "GENERATED_FILE_WRITE_FAILED"
  | "MANAGED_FILE_SAVE_FAILED"
  | "FILE_ASSOCIATION_SAVE_FAILED"
  | "FILE_NOT_FOUND"
  | "FILE_PATH_DENIED"
  | "FILE_SAVE_AS_FAILED"
  | "PROFILE_MISMATCH";
```

UI 显示：

| 错误          | 用户提示               |
| ----------- | ------------------ |
| 写入失败        | 报告文件创建失败，请重试       |
| 目录失败        | 无法创建报告目录           |
| 文件不存在       | 报告文件已经移动或删除        |
| Profile 不匹配 | 当前 Profile 无权访问此文件 |
| 另存为失败       | 无法保存到所选位置          |
| 用户取消        | 不显示错误              |

禁止向 UI 返回完整 Stack Trace。

## 14. 安全要求

1. Renderer 不直接访问文件系统。
2. 文件名必须清洗。
3. Session ID 必须清洗后才能作为目录段。
4. 必须执行路径 canonicalization。
5. 不允许 `..` 路径逃逸。
6. 不允许符号链接绕过授权目录。
7. 不允许通过 IPC 指定任意输出目录。
8. 另存为路径只能来自 Electron Dialog。
9. 不自动信任 LLM 返回的本地路径。
10. 不把报告正文写入日志。
11. 日志只记录 `fileId`、Session ID 和错误码。
12. 文件事件必须校验 Profile。
13. 文件查询必须同时使用 Profile 与 Session。
14. 不同 Profile 的数据库结果必须隔离。

---

## 15. 兼容性要求

### 15.1 旧消息

历史 Assistant Message 即使没有 ManagedFile，也应显示“文档预览”和“保存为 `.md`”。

### 15.2 旧图片附件

现有图片附件表继续使用。

本版本不修改：

```text
session-attachment-store
```

### 15.3 旧 Attachment

现有：

```ts
Attachment
```

继续保留。

Agent Output 文件使用 ManagedFile，不强制转换为旧 Attachment。

### 15.4 Session 删除

删除 Session 时：

* 删除 FileAssociation。
* 不立即删除物理文件。
* 后续由孤儿文件清理策略处理。
* 用户另存为的目标文件不受影响。

---

## 16. 非功能要求

### 16.1 性能

* 文档预览不得阻塞 SSE。
* 创建 Markdown 文件应在 500ms 内完成。
* Session Files 查询应在 200ms 内完成。
* 创建成功后面板应在 1 秒内刷新。
* 不在 React State 中复制多份长 Markdown。
* 文件事件不得造成重复无限刷新。
* 相同 Message 重复点击不得生成大量重复文件。

### 16.2 稳定性

* 创建文件失败不影响当前 Chat。
* 另存为取消不影响 Agent Output。
* File Preview 失败不影响消息显示。
* Agent Output 文件丢失时仍保留记录并显示 `missing`。
* Session 切换后旧事件不得刷新新 Session。

### 16.3 可维护性

* Message UI 不直接调用数据库。
* IPC Handler 不直接包含数据库 SQL。
* 文件写入、存储、关联职责分离。
* 文件名生成独立测试。
* P0 与 P1 可独立交付。
