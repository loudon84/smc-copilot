# 2. 背景

当前 Copilot Desktop 同时负责：

1. 安装 Hermes Agent。
2. 定位 Hermes 运行目录。
3. 创建 Python 虚拟环境。
4. 启动和停止 Hermes Gateway。
5. 读写 Hermes 配置。
6. 管理 API Key。
7. 提供 Chat、Session、Profile、MCP 和设置页面。

安装、运行时管理和桌面界面存在直接依赖：

```text
App.tsx
  → checkInstall
  → hasApiKey
  → Welcome / Installing / Setup
  → installer.ts
  → hermes.ts
  → Hermes Gateway
```

本项目已经提前完成：

```text
Hermes Agent 安装
Hermes 模型配置
Provider 配置
模型凭证配置
Gateway 基础配置
```

Copilot Desktop 不再承担 Hermes Agent 安装和首次模型配置。

# 4. 产品边界

## 4.1 Copilot Desktop 负责

1. 用户登录。
2. 读取本地连接配置。
3. 定位已有 Hermes Runtime。
4. 检测 Gateway 健康状态。
5. 过渡期内启动已有 Hermes Gateway。
6. 连接 Gateway。
7. Chat、Session、Profile、MCP 和应用设置。
8. 展示连接错误和运行日志。
9. 保存用户选择的 Hermes Home。
10. 发送 Chat 请求并接收流式事件。

## 4.2 Copilot Desktop 不负责

1. 安装 Hermes Agent。
2. 更新 Hermes Agent。
3. 修复 Hermes Agent 依赖。
4. 创建 Python 环境。
5. 执行系统包管理器。
6. 写入 Provider API Key。
7. 判断某个固定 API Key 是否存在。
8. 因模型配置异常阻止 Desktop 启动。
9. 卸载 Hermes Agent。
10. 删除 Hermes 数据目录。

## 4.3 过渡期保留

v1.2 暂时保留以下能力：

```text
Hermes Runtime 路径定位
Gateway start / stop / restart
Gateway health check
Profile 端口解析
API_SERVER_KEY 读取
Chat HTTP / SSE
CLI fallback
本地运行日志
```

独立 Runtime Service 接入后，再迁移 Gateway 生命周期和 CLI fallback。

# 9. Runtime Adapter

新增：

```text
src/main/runtime/
├─ runtime-manager.ts
├─ runtime-contract.ts
├─ hermes-runtime-paths.ts
├─ hermes-runtime-locator.ts
├─ legacy-local-runtime-adapter.ts
└─ runtime-errors.ts
```

接口：

```ts
export interface HermesRuntimeAdapter {
  probe(profile?: string): Promise<HermesRuntimeProbe>;

  ensureReady(
    profile?: string,
  ): Promise<HermesRuntimeConnectionResult>;

  getStatus(
    profile?: string,
  ): Promise<HermesRuntimeProbe>;

  restart(
    profile?: string,
  ): Promise<HermesRuntimeConnectionResult>;
}
```

## 9.1 `probe()`

只执行检查，不修改系统。

检查项：

1. Hermes Home 是否存在。
2. Hermes Repo 是否存在。
3. Hermes Python 是否存在。
4. Hermes CLI 是否可调用。
5. Profile 配置是否存在。
6. Profile Gateway 端口。
7. Gateway `/health`。
8. Gateway 鉴权。
9. Hermes 版本。

不得执行：

```text
安装
升级
依赖修复
配置迁移
写入模型配置
写入 API Key
```

## 9.2 `ensureReady()`

执行顺序：

```text
probe
  ↓
Gateway 已健康
  → 返回 ready
  ↓
Runtime 不存在
  → 返回 runtime_missing
  ↓
Runtime 无效
  → 返回 runtime_invalid
  ↓
Gateway 未运行
  → startGatewayWithRecovery
  ↓
等待 health
  ↓
验证鉴权
  ↓
返回 ready 或错误
```

# 16. Chat 连接门禁

## 16.1 输入框状态

Chat 输入框必须在以下状态禁用：

```text
runtime_missing
runtime_invalid
gateway_stopped
gateway_starting
gateway_unreachable
gateway_auth_failed
```

`ready` 时启用。

## 16.2 发送前检查

发送消息前执行轻量状态检查：

```ts
if (!runtime.ready) {
  showConnectionError();
  return;
}
```

Main Process 的发送入口再次执行：

```text
Gateway 健康检查
  ↓
失败时调用 ensureReady
  ↓
仍失败则返回明确错误
```

Renderer 检查用于界面控制。

Main Process 检查用于防止竞态。

## 16.3 模型错误

模型请求失败时：

1. 不跳转 Setup。
2. 不退出主界面。
3. 不判断固定 API Key。
4. 在 Chat 中显示 Hermes 返回的错误。
5. 提供“打开模型设置”和“查看日志”。

错误示例：

```text
已连接 Hermes Gateway，但当前模型请求失败。

Provider: alibaba
Model: qwen-plus
错误: authentication failed
```

# 18. Profile 处理

每个 Profile 必须独立解析：

```text
Hermes Home
config.yaml
.env
state.db
Gateway 端口
API_SERVER_KEY
Gateway 进程状态
```

Profile 切换流程：

```text
用户切换 Profile
  ↓
停止当前 Chat 请求
  ↓
RuntimeProvider.connect(newProfile)
  ↓
检测对应 Gateway
  ↓
必要时启动对应 Gateway
  ↓
连接成功
  ↓
刷新 Session 和 Chat
```

禁止默认固定使用 `127.0.0.1:8642`。

必须调用现有 Profile 端口分配逻辑。

# 19. 错误码

| 错误码                    | 说明                 | 页面处理             |
| ---------------------- | ------------------ | ---------------- |
| `RUNTIME_NOT_FOUND`    | 未找到 Hermes Runtime | Connection Error |

| `CLI_NOT_AVAILABLE`    | Hermes CLI 不可调用    | Connection Error |
| `GATEWAY_START_FAILED` | Gateway 启动失败       | Connection Error |

| `CHAT_REQUEST_FAILED`  | Chat 请求失败          | Chat 内显示         |

不得将模型错误映射为 Runtime 安装错误。
