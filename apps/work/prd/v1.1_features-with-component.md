# Hermes Desktop 文件管理与富内容组件克隆实施 RPD

版本：v1.1
目标：从“组件骨架”推进到“真实可用功能”
执行环境：Cursor
参考源码：`references/chatbox`
参考说明：`wiki/wiki_chatbox.md`

---

# 1. 实施目标

本次实施不是复制 Chatbox 文件，而是完成以下真实业务闭环：

```text
选择/拖入/粘贴文件
  → 文件识别
  → 附件状态显示
  → 文件解析
  → 消息发送
  → 消息附件恢复
  → 文件内容预览
  → 加入当前 Session 上下文
  → 大文件分块检索
```

富内容输出闭环：

```text
Hermes SSE 流式输出
  → Markdown 增量显示
  → 识别代码围栏
  → 普通代码高亮
  → Mermaid 图表
  → SVG 安全预览
  → HTML Artifact 沙箱预览
```

完成后，用户应当能实际执行：

1. 在 Composer 中选择多个文件。
2. 将文件拖入 Chat。
3. 粘贴截图或本地文件。
4. 查看解析进度和错误。
5. 发送文本、图片、PDF、Office 和代码文件。
6. 在历史消息中重新打开附件。
7. 在右侧面板预览附件内容。
8. 将附件加入或移出 Session 上下文。
9. 对大文件进行会话级内容检索。
10. 查看 Mermaid、SVG 和 HTML Artifact。

# 2. Cursor 工作原则

## 2.1 参考目录不得进入产品依赖

必须在 `tsconfig`、Vite 和 ESLint 层排除：

```text
references/**
wiki/**
```

检查：

```bash
grep -R "references/chatbox" src package.json electron.vite.config.ts
```

结果必须为空。

产品代码不得出现：

```ts
import ... from "../../../references/chatbox/..."
```

也不得：

* 运行时读取 `references/chatbox`
* 打包 Chatbox 文件
* 复制 Chatbox Store
* 使用 Chatbox IPC
* 使用 Chatbox 数据库
* 引入 Chatbox MUI/Mantine 组件链

`references/chatbox` 只允许作为 Cursor 的源码检索语料。

---

## 2.2 每次只克隆一个垂直能力

错误方式：

```text
一次创建 30 个文件
→ 每个文件只有 interface 或 TODO
→ 没有接入真实 Chat
```

正确方式：

```text
选择文件
→ AttachmentTray 显示
→ 发送给 Hermes
→ Session 恢复
→ 测试通过

然后再开发下一项
```

每个迭代必须满足：

```text
Source Analysis
→ Hermes Mapping
→ Implementation
→ Integration
→ Test
→ Commit
```

---

## 2.3 Chatbox 源码阅读顺序

Cursor 不应一次读取整个 Chatbox。

针对一个功能，只读取：

```text
1. wiki/wiki_chatbox.md 对应章节
2. 用户入口组件
3. 该组件直接 import 的文件
4. 状态来源
5. IPC 或 Main Process 实现
6. Shared 类型
7. 测试
```

例如附件功能：

```text
references/chatbox/src/renderer/components/InputBox/Attachments.tsx
  ↓
搜索 FileMiniCard 的调用方
  ↓
搜索附件状态字段的定义
  ↓
搜索状态由哪个 Store 更新
  ↓
搜索 Store 调用的 IPC
  ↓
搜索 Main Process Handler
```

不能只读取一个 JSX 文件，然后模仿其样式。

## 4.2 保留旧 Attachment

Hermes 当前附件只有三种类型：

```ts
"image" | "text-file" | "path-ref"
```

并对图片、文本大小和文件数量已有约束。

禁止直接修改所有旧调用。

创建适配器：

```text
src/shared/files/legacy-attachment-adapter.ts
```

```ts
export interface ManagedFileAttachmentPayload {
  managedFile: ManagedFile;
  legacyAttachment: Attachment;
}

export function managedFileToAttachment(
  file: ManagedFile,
  resolved: {
    dataUrl?: string;
    text?: string;
    path?: string;
  },
): Attachment {
  if (file.category === "image" && resolved.dataUrl) {
    return {
      id: file.id,
      kind: "image",
      name: file.name,
      mime: file.mime,
      size: file.size,
      dataUrl: resolved.dataUrl,
      path: resolved.path,
    };
  }

  if (
    ["text", "markdown", "code"].includes(file.category) &&
    resolved.text
  ) {
    return {
      id: file.id,
      kind: "text-file",
      name: file.name,
      mime: file.mime,
      size: file.size,
      text: resolved.text,
    };
  }

  if (!resolved.path) {
    throw new Error("A path-ref attachment requires a resolved path");
  }

  return {
    id: file.id,
    kind: "path-ref",
    name: file.name,
    mime: file.mime,
    size: file.size,
    path: resolved.path,
  };
}
```

第一阶段发送流程仍然是：

```text
ManagedFile
→ adapter
→ Attachment
→ 原 sendMessage 流程
```

Chatbox 通过统计 Markdown 中的三反引号数量，判断当前哪个代码块仍在生成，避免提前运行 Mermaid 或 Artifact。

在 Hermes 建立：

```ts
export function getStreamingFenceState(
  markdown: string,
): {
  fenceCount: number;
  openFenceIndex: number | null;
}
```

规则：

```text
fenceCount 为偶数
  → 所有 block 完成

fenceCount 为奇数
  → 最后一个 block 为 streaming
```

对于 streaming block：

| 类型      | 行为       |
| ------- | -------- |
| 普通代码    | 正常增量显示   |
| Mermaid | 显示源码，不运行 |
| SVG     | 显示源码，不渲染 |
| HTML    | 显示源码，不运行 |

# 21. Preload 设计

```ts
export const filesApi = {
  pick: (
    options?: PickFilesOptions,
  ): Promise<PickedFileDescriptor[]> =>
    ipcRenderer.invoke("files:pick", options),

  importPaths: (
    input: ImportFilePathsInput,
  ): Promise<ManagedFile[]> =>
    ipcRenderer.invoke("files:import-paths", input),

  getPreview: (
    input: GetFilePreviewInput,
  ): Promise<FilePreviewDescriptor> =>
    ipcRenderer.invoke("files:get-preview", input),

  retryParse: (
    input: RetryParseInput,
  ): Promise<void> =>
    ipcRenderer.invoke("files:retry-parse", input),

  onJobEvent: (
    callback: (event: FileJobEvent) => void,
  ): (() => void) => {
    const handler = (
      _event: Electron.IpcRendererEvent,
      payload: FileJobEvent,
    ): void => callback(payload);

    ipcRenderer.on("file-job:event", handler);

    return () => {
      ipcRenderer.removeListener(
        "file-job:event",
        handler,
      );
    };
  },
};
```

fs
