# Copilot Desktop 报告预览、另存为与 Agent Output 闭环 PRD

**版本：v1.1.2**
**目标项目：** `https://github.com/loudon84/copilot-desktop`
**适用模块：** Chat、Message、File Preview、Session Files、Agent Output、Main File Service
**实施环境：** Cursor
**状态：** 待开发

---

## 1. 项目背景

Copilot Desktop 已根据前序文件管理 RPD 建立部分基础能力：

```text
Chat
├─ FilePreviewPanel
├─ SessionFilesPanel
├─ useFilePreview
└─ useSessionFiles
```

现有实现能够承载“已注册 ManagedFile”的预览和 Session 文件分组，但尚未完成 Assistant Markdown 报告的文件化闭环。

当前实际流程：

```text
Hermes Agent
  → SSE 返回 Markdown
  → Assistant Message
  → Chat 页面显示报告
```

缺失流程：

```text
Assistant Message
  → 文档识别
  → 文档预览
  → 创建受管 Markdown 文件
  → 创建 ManagedFile
  → 创建 FileAssociation
  → Agent Output 展示
  → 另存为
  → Session 恢复
```

因此，用户虽然可以在 Chat 中阅读报告，但无法：

* 独立预览文档；
* 保存为 `.md`；
* 在 Agent Output 中再次打开；
* 重启应用后继续管理；
* 将 Hermes 实际创建的文件自动注册为输出成果。

## 2. 当前代码问题

### 2.1 Chat 页面仅支持 ManagedFile 预览

现有 `useFilePreview` 以 `fileId` 为入口：

```text
fileId
→ files:get-preview
→ FilePreviewDescriptor
→ FilePreviewPanel
```

Assistant 报告只有：

```text
message.content
```

没有：

```text
fileId
managedPath
FileAssociation
```

所以现有 File Preview 无法直接预览普通 Assistant 报告。

### 2.2 Message 层缺少文档操作

当前 Message 组件未实现：

```text
MessageDocumentActions
├─ 文档预览
├─ 保存为 .md
└─ 加入 Agent Output
```

Assistant 长 Markdown 仍被当作普通聊天内容。

### 2.3 Files API 缺少消息转文件接口

现有 Files API 即使包含 `saveAs`，也只能保存已有 `fileId`。

缺少：

```text
files:create-from-message
```

因此无法执行：

```text
message.content
→ ManagedFile
→ saveAs(fileId)
```

### 2.4 Main Process 文件能力不完整

现有 UI、Preload 或 Shared Contract 即使已建立，Main Process 必须实际注册对应 IPC Handler。

至少需要确认并实现：

```text
files:get-capabilities
files:list-session
files:get-preview
files:create-from-message
files:save-as
files:open
files:reveal
```

若 Main 未注册，运行时将出现：

```text
No handler registered for 'files:*'
```

### 2.5 Agent Output 缺少自动刷新

当前 Session Files 主要在 Session 或 Profile 切换时刷新。

文件创建后若没有 File Domain Event：

```text
ManagedFile 已创建
→ Session Files 未刷新
→ Agent output 仍显示 No agent files
```

## 3. 产品定位

本版本建设：

```text
Report Output Pipeline
```

负责将 Hermes 输出的 Markdown 报告转化为可预览、可保存、可恢复和可管理的文档资产。

统一支持两种输出路径。

### 3.1 消息型报告

Hermes 只输出 Markdown 消息：

```text
Assistant Markdown
→ Message Preview
→ Create Managed File
→ Agent Output
→ Save As
```

该路径为本版本 P0。

### 3.2 文件型报告

Hermes 使用文件工具创建真实文件：

```text
Hermes File Tool
→ Structured Artifact Event
→ Register Existing File
→ Agent Output
```

该路径为本版本 P1。

两条路径最终统一为：

```text
ManagedFile
+
FileAssociation(role = "agent-output")
```

## 4. 建设目标

### 4.1 用户目标

用户能够：

1. 在 Assistant 报告消息中点击“文档预览”。
2. 在右侧独立预览完整 Markdown。
3. 将报告保存为 `.md`。
4. 将报告加入 Agent Output。
5. 在 Agent Output 中再次预览。
6. 使用系统另存为保存到指定目录。
7. 重启并恢复 Session 后继续访问报告。
8. 在不同 Profile 中保持文件隔离。
9. Hermes 真正创建文件后自动显示为 Agent Output。

### 4.2 技术目标

形成完整链路：

```text
Renderer
→ Preload
→ IPC
→ Main File Service
→ SQLite / Profile Storage
→ File Domain Event
→ Renderer Refresh
```

本版本不包含：

* 不修改 Hermes Agent 主循环；
* 不替换现有 Chat SSE；

* 不重构整个 Chat 页面；
* 不实现云文件同步；
* 不实现多人协同编辑。

## 6. 核心设计原则

### 6.1 消息与文件分离

```text
Assistant Message ≠ ManagedFile
```

Assistant Message 是对话记录。

ManagedFile 是文件资产。

### 6.2 预览与落盘分离

“文档预览”直接使用消息内容，不要求先创建物理文件。

“保存为 `.md`”才进入文件创建流程。

### 6.3 另存为由 Main Process 完成

```text
Renderer
→ files:save-as
→ dialog.showSaveDialog
→ copyFile
```

Renderer 不得接触目标路径和文件系统。

### 6.4 Profile 强隔离

所有报告文件必须写入当前 Profile 根目录。

### 6.5 结构化注册

只有以下来源允许注册 Agent Output：

* 用户主动保存消息报告；
* 已知文件工具的结构化结果；
* Hermes Artifact 事件；
* 已授权 Workspace 中的真实文件。

## 12. 文件名处理

```ts
export function sanitizeGeneratedFileName(
  title: string,
): string {
  const cleaned = title
    .normalize("NFKC")
    .replace(/[<>:"/\\|?*\u0000-\u001F]/g, "-")
    .replace(/\s+/g, " ")
    .replace(/\.+$/g, "")
    .trim()
    .slice(0, 80);

  return cleaned || "generated-report";
}
```

标题来源优先级：

```text
1. 消息第一行 Markdown Heading
2. suggestedTitle
3. Session Title
4. generated-report
```

文件重名处理：

```text

客户画像报告 (2).md
```

## 14. Preload 设计

```ts
export const filesApi: HermesFilesAPI = {
  createFromMessage: (input) =>
    ipcRenderer.invoke(
      FILES_IPC_CHANNELS.createFromMessage,
      input,
    ),

  saveAs: (input) =>
    ipcRenderer.invoke(
      FILES_IPC_CHANNELS.saveAs,
      input,
    ),

  onFileDomainEvent: (callback) => {
    const handler = (
      _event: Electron.IpcRendererEvent,
      payload: FileDomainEvent,
    ): void => callback(payload);

    ipcRenderer.on("files:event", handler);

    return () => {
      ipcRenderer.removeListener(
        "files:event",
        handler,
      );
    };
  },

  // 其它 API
};
```

## 15. Assistant 文档识别

创建：

```text
document-message-utils.ts
```

```ts
export function isDocumentLikeMessage(
  content: string,
): boolean {
  const text = content.trim();

  if (text.length < 300) {
    return false;
  }

  const hasHeading = /^#{1,6}\s+/m.test(text);
  const hasTable =
    /\|.+\|[\r\n]+\|[-:\s|]+\|/.test(text);
  const paragraphCount =
    text.split(/\n\s*\n/).filter(Boolean).length;

  return (
    hasHeading ||
    hasTable ||
    paragraphCount >= 4
  );
}
```

仅控制是否显示操作按钮。

不自动写文件。
