# v1.1 结构对齐（Structure Alignment）

## 背景与结论

当前实现（对应旧 v1.0 路线图）已经**功能完整并全绿**：`typecheck` 通过、`npm test` 181 文件 / 1842 用例全部通过、组件已接入 Chat（`ChatInput` 的 `AttachmentTray`、`MessageRow` 的 `MessageAttachmentGrid`、`Chat` 的 `FilePreviewPanel`/`SessionFilesPanel`、`rich-content/*`），Preload `hermesAPI.files` 与 Main `registerFilesIpcHandlers` 均已连线。

本轮**不是加功能**，而是把现有代码**重排/更名为 v1.1 规定的目录与文件布局**，逐处更新 import（不保留兼容 shim），保持行为不变，并保证四项校验全绿：`typecheck` / `test` / `build` / `lat check`。你负责手动验证运行效果。

已确认：磁盘上每个逻辑路径只有**一个**物理文件（初始 `git status` 里出现的反斜杠路径是列表显示假象，非真实重复文件），无需危险删除。

## 范围边界

- 明确**不在本轮**（属新功能，非重排）：v1.1 §15 异步解析任务队列 `src/main/files/jobs/`（`file-job:event` / preload `onJobEvent`）、v1.1 §14.3 `LocalMarkItDownProvider`。当前不存在这些文件，且 PRD 禁止提交空骨架，故不创建占位。
- 保留 v1.1 未列出但**必需**的现有模块（如 `parser-contract.ts`、`file-status.ts`、`file-config.ts`、`file-index-service.ts`、`file-context-builder.ts`、`file-cleanup-service.ts`、`FileContextMenu`/`FileOperationCard`/`FileIcon`/`FileBadge`），归入合理子目录，不删除。
- 每个阶段结束跑：`npm run typecheck && npm test && npm run build`，再 `lat check`。

## 关键风险与缓解

- **import 面广**：用 Grep 全量定位每个被移动/更名符号的引用，逐处更新；桶文件 `index.ts` 保持导出符号名不变，最小化外部改动。
- **lat check 必过**：`lat.md/*` 大量 `[[src/...#symbol]]` 源码链接引用旧路径/符号；每阶段同步更新，阶段末 `lat check`。
- **测试路径**：colocated 测试（`*.test.ts`）随模块移动并更新相对 import；新增拆分文件若无独立测试则由既有测试经桶导出覆盖，不新增空测试。
- **无 shim 要求**：删除旧文件后立即修复所有引用，靠 `typecheck` 兜底确保无悬挂 import。
