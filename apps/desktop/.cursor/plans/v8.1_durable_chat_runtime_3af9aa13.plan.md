# v8.1.0 Durable Chat Runtime (PR1–PR5) 实施计划

## 基线与范围

- 基线：v8.0.5 已完成 runId+turnId+requestId 命令契约（见 `specs/current-agent-state.md`，全部 done）
- 本次范围：**PR1–PR5**；PR6（Electron E2E）、PR7（Deprecated 清理/Cutover）顺延，写入 state 文件
- 持久化位置：复用 profile `state.db`（可写模式先例：`src/main/chat-files/platform/db.ts` 的 `getDbConnection(false)`）
- 状态机纪律：每阶段更新 `specs/current-agent-task.md` / `current-agent-state.md` / `current-agent-log.md`

## 现状关键问题（PRD §一，已核实源码）

- `chat-runtime:submit` 是长 Pending invoke（`chat-runtime-ipc.ts` 返回 `promise` 直到 turn 结束）
- `finishOnce()` 调 `clearActiveRun(runId)` → stream 结束后 pending interaction 丢失、command 得 `RUN_NOT_FOUND`
- PendingInteraction 仅存 `ChatRunHandle.pendingInteractions` 内存 Map
- `HermesChatCommandAdapter` 用 `stream:false` follow-up，不回流事件
- `useChatQueue.dequeue()` 依赖 setState updater 同步执行，非原子
- Retry 只有 `lastTurnSnapshotRef` 单槽，未按 turnId 绑定；`retryLastTurn` 未传 `skipAppendUser`

## PR1 — Event-driven Runtime Contract

**Shared**（`src/shared/chat-runtime/`）
- `chat-runtime-events.ts`：`ChatRuntimeEventBase` 增加 `eventId` / `sequence` / `emittedAt`；新增事件 `interaction.accepted` / `interaction.continuing`（`interaction.resolved` 复用现有 `clarify.resolved`/`approval.resolved` 语义或新增统一类型，以 PRD §7.3 为准）
- `chat-runtime-contract.ts`：新增 `ChatStartInput` / `ChatStartResult`（`{ok:true, runId, turnId, acceptedAt}`）；`CHAT_RUNTIME_CHANNELS` 增加 `start` / `state` / `recover`；旧 `submit` 标注 deprecated 保留为兼容适配
- 新建 `chat-runtime-state.ts`：`DurableChatRunState`、`ChatTransportHandle`、`PendingInteractionRecord`、`ChatTurnStatus`
- 新建 `chat-runtime-trace.ts`：`ChatRuntimeTrace` 类型（禁止记录 prompt/secret 正文）

**Main**（`src/main/chat-runtime/`）
- 新建 `chat-event-sequencer.ts`：per-turn 单调递增 sequence + eventId 分配；SSE 回调与 `chat-session-reconciler.ts` 事件统一经 sequencer 出口，禁止旁路直发
- `chat-runtime-ipc.ts`：新增 `chat-runtime:start` handler —— 校验 + 持久化 turn 占位（PR2 接入 store，PR1 先内存）后立即返回 accepted；turn 生命周期全部走 `chat-runtime:event`；旧 `submit` 改为薄适配层（内部调 start 逻辑 + 等待终态事件拼 `ChatSubmitResult`）

**Preload / Renderer**
- `src/preload/chat-runtime-api.ts` + `index.d.ts`：增加 `start` / `getState` / `recover` 声明
- `ports/ChatRuntimePort.ts`、`adapters/aios/aiosChatRuntimeAdapter.ts`：新增 `start`
- `controller/useChatController.ts` `submitMessage`：改用 `runtime.start`，完成/失败完全由 onEvent 驱动（移除对 submit 返回值的 sessionId 绑定依赖，`session.started` 事件已覆盖）

**验收**：start IPC 在 Agent 执行完成前立即返回；事件带唯一 eventId 与递增 sequence；契约单测（`tests/chat-runtime-start-v810.test.ts`）

## PR2 — Durable Runtime Store（state.db）

**Main**
- 新建 `chat-runtime-store.ts`：经 `getDbConnection(false)`（`src/main/chat-files/platform/db.ts`）打开当前 profile `state.db`，建表 `chat_runtime_run` / `chat_runtime_turn` / `chat_runtime_event` / `chat_pending_interaction` / `chat_queue_entry`（字段按 PRD §6）；`CREATE TABLE IF NOT EXISTS` 幂等
- 新建 `chat-transport-registry.ts`：`{runId, turnId, abort()}` 传输句柄注册表，与 run 状态分离
- `chat-runtime-ipc.ts` 重构：`finishOnce` 只删 transport handle + 写终态到 store，**不再** `clearActiveRun` 抹掉 pending interaction；clarify/approval requested 时写入 `chat_pending_interaction`
- `chat-interaction-registry.ts`：校验数据源从内存 Map 改为 store 优先（内存作缓存）

**验收**：原 stream 结束（onDone）后 approval 命令仍可处理，不再 `RUN_NOT_FOUND`；单测模拟 stream 关闭后 resolve（`tests/chat-runtime-durable-store-v810.test.ts`）

## PR3 — Interaction Continuation Pipeline

**Main**
- 新建 `hermes-interaction-continuation-adapter.ts`（实现 shared 的 `HermesInteractionContinuationAdapter`）：
  - P1：启动探测 Gateway capability（`clarify_response` / `approval_response` / `session_continuation`），存在则走原生 API
  - P2：fallback 用 `sendMessage()` 流式链路（同 session/profile/model/work context），**禁止** `fetch(stream:false)`；continuation 的 message.delta / tool.event / usage / completed 经 sequencer 回流同 runId+turnId
  - P3：不支持则 `GATEWAY_UNSUPPORTED`，禁止静默模拟成功
- 命令 handler 语义调整（PRD §7.3）：HTTP 接受后发 `interaction.accepted`；gateway 确认续跑发 `interaction.continuing`；continuation 终态才发 `*.resolved`；失败发 `interaction.failed`
- 现有 `hermes-chat-command-adapter.ts` 保留为兼容路径，被新 adapter 包装

**Renderer**
- `chatRuntimeEventReducer.ts` / `chatReducer.ts`：处理 `interaction.continuing` 中间态；Clarify/Approval Card（`components/clarify/ClarifyCard.tsx`、`components/approval/ApprovalCard.tsx`）显示「已接受，继续执行中」状态

**验收**：Clarify/Approval 回答后同一 Chat 内看到后续 stream 输出；单测覆盖三优先级与失败路径（`tests/chat-interaction-continuation-v810.test.ts`）

## PR4 — Turn Ledger、Retry 与 Queue

**Renderer**（`src/renderer/src/modules/chat/`）
- 新建 `controller/chatTurnLedger.ts`：`turnId → {snapshot, userMessageId, assistantMessageId, errorMessageId, status, usage}` 映射，替代单槽 `lastTurnSnapshotRef`
- `controller/chatViewTypes.ts`：所有 view item 增加 `turnId?`；`chatReducer.ts` append 消息时落 turnId
- 新建 `controller/chatRetryService.ts`：
  - `retryTurn(turnId)`：按 ledger 找原 snapshot，复用原 user message（`skipAppendUser` 语义修正），删除/替换失败 assistant+error 行，新建 turn 重放
  - `editAndRetry(turnId)`：经新建 `ports/ChatRunContextPort.ts`（`getContext`/`restoreContext`）恢复 expert/team/skill/workMode/permission/promptHint 到 workspace，不自动发送
  - `retryWithCurrentContext(turnId)`：保留原文本/附件，用当前 model/expert/skill 等
- `hooks/useChatQueue.ts` 重构为 reducer（`enqueue/remove/move/mark_running/complete`），drain 从 state 读 `queue[0]` 后 dispatch `mark_running`，废弃 updater 返回值出队；queue entry 状态机 `queued/running/completed/failed/cancelled`
- Queue 持久化：enqueue/remove/move 经 preload 新通道写入 `chat_queue_entry`；启动恢复
- Queue UI（`components/composer/QueuedMessages.tsx`）：删除、改文本、拖动排序、立即执行、暂停 auto-drain（按 PRD §11.2）

**验收**：多个失败 turn 各自 Retry 不重放错误请求、不重复 user message；单测（`tests/chat-turn-ledger-retry-v810.test.ts`、`tests/chat-queue-reducer-v810.test.ts`）

## PR5 — Recovery 与 Diagnostics

**Main**
- 新建 `chat-recovery-coordinator.ts`：app 启动扫 `chat_runtime_turn` 中 `starting/streaming/waiting_*` → 对 session DB / gateway 查证 → completed / interrupted / 恢复 waiting card；queue 未执行 entry 恢复；不重放失败 turn
- `chat-runtime-ipc.ts`：实现 `chat-runtime:get-state`（run+turn+pending+queue+usage）与 `chat-runtime:recover`
- 结构化 trace 日志（`chat-runtime-trace.ts` 落地，脱敏）+ `Export Chat Diagnostics` IPC（runtime metadata / event timeline / tool timeline / error / file ids，无敏感正文）

**Renderer**
- 新建 `hooks/useChatRuntimeRecovery.ts`：挂载后调 `getState` 恢复 run/turn/partial messages/pending interaction/queue；事件按 `sequence <= lastAppliedSequence` 去重丢弃（PRD §8.3）
- `components/diagnostics/`：诊断导出入口（挂到 Chat 面板或 Settings，按现有模式从简）

**验收**：renderer reload 后 pending approval 卡片恢复且可操作；重复/迟到事件不二次应用；单测（`tests/chat-runtime-recovery-v810.test.ts`）

## 关键风险

- state.db 为 Python hermes-agent 所有：只 `CREATE TABLE IF NOT EXISTS` 新表，不碰已有表结构；写连接失败时降级为内存 + 警告日志
- submit→start 切换影响 `AiosCopilotChatHost` / `MultiRunChatShell` 现有行为，保留 `VITE_CHAT_ENGINE=legacy` 回退不动
- capability 探测结果需缓存，避免每次命令都探测
