# PRD v7.7_chat-task-window

版本：v7.7
主题：Chat 页面任务窗口化
前置架构：延续 v7.6，`copilot-desktop` 只操作用户交互和配置 `hermes-agent`，所有 Expert / Skill / MCP 调用均由 `hermes-agent API_SERVER :8642` 执行。

---

## 1. 源码分析结论

当前 Chat 页面已经具备可复用基础：

```text
src/renderer/src/screens/Hermes/pages/Chat/
  ├─ HermesDefaultWebChatSurface.tsx
  ├─ HermesDefaultChatPage.tsx
  ├─ ChatScrollArea.tsx
  ├─ ComposerBar.tsx
  ├─ ChatBubble.tsx
  ├─ ActivityRow.tsx
  ├─ ErrorCard.tsx
  ├─ UsageRow.tsx
  ├─ components/
  └─ hooks/
```

GitHub 目录中已经存在 `ChatScrollArea / ComposerBar / ChatBubble / ActivityRow / ErrorCard / UsageRow` 等组件，说明当前 Chat 页不是单文件实现，适合继续按组件拆分方式扩展。([GitHub][1])

`HermesDefaultWebChatSurface` 当前已经组合了 `ChatScrollArea`、`ComposerBar`、`HermesActiveExpertBar`、`StatusToast` 和 `useHermesDefaultWebChat`，发送逻辑最终走 `stream.send(...)`，这符合 v7.6 的统一 hermes-agent 发送链路。([GitHub][2])

`ComposerBar` 已经预留 `workControlsSlot`，并且已有模型选择、附件、更多操作、Stop / Send 工具栏结构；v7.7 的 Expert / Skill Selector、Prompt Hint Composer 应优先挂载到这个 slot，不重写输入区。([GitHub][3])

`ChatScrollArea` 已经引入 `ToolProgressTimeline`、`LocalDocumentCard`、`extractLocalDocumentPaths`，说明 Tool Progress 与本地文档卡片已经有雏形；v7.7 应做结构化增强，而不是重新设计一套消息渲染系统。([GitHub][4])

`useHermesDefaultChatStream` 已经订阅 `onChunk / onToolProgress / onUsage / onDone / onError`，并通过 `chatApi.chat.sendMessage(...)` 发送 `history / attachment_ids / model_id / expert_id / team_id / work_mode / invocation_source`，可直接作为 v7.7 的 Hermes stream event rendering 基础。([GitHub][5])

## 2. 产品定位

v7.7 的 Chat 页面不再只是对话页面，而是：

```text
Chat Task Window
= 任务窗口
= Agent 对话流
+ Expert / Skill Prompt Hint
+ Tool Progress Timeline
+ Local Document Output
+ Task Lifecycle
```

产品结构保持此前定义：Copilot Desktop 正式结构是 `Work 工作台 + Web 工作台`，其中 `Work / 任务 / 任务窗口` 是核心操作平面；原“会话 / 运行 / 成果中心”应收敛为任务、任务事件和任务输出。

---

## 3. v7.7 目标

```text
1. 保留现有 Chat 页面 UI 风格，不重做整页视觉系统。
2. 在现有 Chat Layout 上增强任务窗口能力。
3. Expert / Skill Selector 只生成 prompt hint。
4. 所有发送继续走 hermes-agent API_SERVER。
5. Tool Progress 使用 hermes-agent stream events 渲染。
6. 文档由 hermes-agent 落盘，desktop 只识别本地路径并展示卡片。
7. 不做旧 direct gateway / taskId / artifactUrl 兼容。
```

## 5. Task Lifecycle

### 5.1 状态定义

```ts
export type ChatTaskStatus =
  | "draft"
  | "ready"
  | "creating"
  | "running"
  | "waiting_tool"
  | "waiting_approval"
  | "completed"
  | "failed"
  | "cancelled";
```

### 5.2 状态映射

```text
idle + no message        → draft
composer has text        → ready
runState = creating      → creating
runState = streaming     → running
onToolProgress           → waiting_tool
onDone                   → completed
onError                  → failed
cancel                   → cancelled
```

### 5.3 UI 展示

新增：

```text
TaskStatusBar
  - 当前任务标题
  - 当前状态
  - 当前 Expert / Skill
  - 当前 Profile
  - 运行时长
```

挂载位置：

```tsx
HermesDefaultWebChatSurface
  ├─ HermesActiveExpertBar
  ├─ TaskStatusBar
  ├─ Search
  └─ ChatScrollArea
```

## 6. Prompt Hint Composer

### 6.1 功能目标

Expert / Skill Selector 不直接触发 MCP，不直接调用 nodeskclaw，只生成发送给 hermes-agent 的 prompt hint。

### 6.2 输入

```ts
interface PromptHintInput {
  userMessage: string;
  expertId?: string;
  expertName?: string;
  skillId?: string;
  skillName?: string;
  mcpServerName?: string;
  outputMode?: "markdown" | "docx" | "pdf";
  attachments?: Array<{
    id: string;
    name: string;
    storagePath?: string;
  }>;
}
```

### 6.3 输出模板

```text
请优先使用当前 hermes-agent 已配置的 MCP Server「{mcpServerName}」中的专家技能「{skillName}」完成任务。

执行要求：
1. 通过 hermes-agent 内部 MCP Client 调用工具。
2. 不要求 desktop 直接调用远端 Expert Gateway。
3. 如工具返回过程信息，请通过工具进度或结构化输出呈现。
4. 如生成文档，请保存到当前 Hermes workspace。
5. 最终回答必须包含本地文件路径。

用户任务：
{userMessage}
```

### 6.4 UI

```text
PromptHintComposer
  ├─ collapsed 默认折叠
  ├─ 展开后显示实际发送内容
  ├─ 支持复制
  ├─ 支持恢复默认模板
  └─ 支持本次发送前编辑
```

挂载位置：

```tsx
<ComposerBar workControlsSlot={<PromptHintComposer />} />
```

## 7. Tool Progress Timeline

### 7.1 事件来源

只消费 hermes-agent stream events：

```text
chat.chunk
chat.tool_progress
chat.usage
chat.done
chat.error
```

不消费 nodeskclaw 原始 SSE。

### 7.2 数据结构

```ts
interface ToolProgressEntry {
  id: string;
  taskId?: string;
  toolName?: string;
  title: string;
  message?: string;
  status: "pending" | "running" | "completed" | "failed";
  timestamp: string;
  raw?: unknown;
}
```

### 7.3 UI 规则

```text
1. running 状态显示在当前 assistant streaming 前。
2. completed 状态折叠为一行。
3. failed 状态进入 ErrorCard。
4. 同一 toolName 的连续 progress 合并。
5. final response 出现后 timeline 默认折叠。
```

## 8. Local Document Output

### 8.1 识别规则

从 streaming content 和 final assistant message 中识别：

```text
file://...
C:\...
/Users/...
~/.hermes/workspace/...
.hermes/workspace/...
```

当前 `ChatScrollArea` 已经使用 `extractLocalDocumentPaths(streamingContent)` 和 `LocalDocumentCard`，v7.7 继续增强该路径识别逻辑。([GitHub][4])

### 8.2 文档卡片

```text
LocalDocumentCard
  ├─ 文件名
  ├─ 文件类型
  ├─ 本地路径
  ├─ 打开文件
  ├─ 打开所在目录
  └─ 复制路径
```

### 8.3 责任边界

```text
文档生成：hermes-agent
文档落盘：hermes-agent
路径返回：hermes-agent final response
卡片展示：copilot-desktop
```


### 9.2 v7.7 扩展

新增内部 reducer：

```ts
type ChatTaskEvent =
  | { type: "task.status"; status: ChatTaskStatus }
  | { type: "chat.chunk"; content: string }
  | { type: "tool.progress"; entry: ToolProgressEntry }
  | { type: "output.document"; path: string }
  | { type: "usage"; usage: unknown }
  | { type: "error"; error: string }
  | { type: "done"; sessionId?: string };
```

新增 Hook：

```text
src/renderer/src/screens/Hermes/pages/Chat/hooks/useChatTaskWindow.ts
```

职责：

```text
1. 包装 useHermesDefaultWebChat
2. 计算 task lifecycle
3. 管理 prompt hint
4. 管理 tool progress timeline
5. 管理 local document outputs
6. 不改动 hermes-agent 发送主链路
```
