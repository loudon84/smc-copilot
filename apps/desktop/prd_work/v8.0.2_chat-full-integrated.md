# 1. 源码复核结论

v8.0.1 已经修复了 Session、History、Abort、Work 参数和部分 Runtime Event，Chat Controller 也已建立。当前主要问题不再是 Main/Preload 契约，而是：

> **生产入口没有真正使用迁入的 copilot-desktop Chat 组件，而是重新编写了一套轻量 Chat UI。**

当前生产链路为：

```text
HermesDefaultChatPage
  → AiosCopilotChatHost
    → ChatSurface
      → 简化 MessageList
      → 简化 ChatComposer
      → 简化 ModelPicker
```

`ChatSurface` 当前只引用 `MessageList`、`ChatComposer` 和 `ModelPicker`，没有真正接入已经迁移的完整 ChatInput、HistoryRow、PromptNavigator、完整文件组件和面板布局。

Cursor 实施计划把“Copilot UI 生产接管、File Platform、多会话、E2E”全部标记为 completed，但实际代码仍存在大量 Lite、Thin 和占位实现。

# 2. 截图问题与源码定位

## 2.1 页面出现空白右栏

截图中 Chat 内容区右侧存在较大的空白区域。

原因是 `AiosCopilotChatHost` 始终传入一个 React Fragment 作为 `filesPanelSlot`，即使其中的 `SessionFilesPanel` 和 `FilePreviewPanel` 都返回 `null`，Fragment 本身仍然是 truthy。

`ChatSurface` 因此始终创建：

```tsx
<aside className="chat-right-panel">
```

而 CSS 固定该面板宽度为 `320px`。

必须改为显式状态：

```ts
showSessionFilesPanel
previewFileId
previewMode
```

只有面板实际打开时才渲染 `aside`。

---

## 2.2 Expert、Skill 信息上下重复

截图中顶部显示：

* Task Status；
* Profile；
* Expert；
* Skill；
* Work Context Chips；

Composer 上方又显示：

* Gateway；
* Expert；
* Skill；
* Permission；
* MCP Host。

这是因为 Host 同时注入：

```text
HermesActiveExpertBar
TaskStatusBar
WorkChatContextBar
PromptHintComposer
WorkComposerControls
```

`WorkChatContextBar` 和 `WorkComposerControls` 都展示 Expert、Skill 和 Permission，形成重复信息。

目标应调整为：

* 顶部只保留 Active Expert、Ask/Plan/Craft；
* TaskStatusBar 只在任务执行中显示；
* Expert、Skill、Permission 只在 Composer 工具栏显示；
* Prompt Hint 改为 Composer 内部弹出面板。

---

## 2.3 Prompt Hint 当前只是展示组件

Host 向 `PromptHintComposer` 传入：

```tsx
userMessage=""
```

并且没有传递 `onHintChange`。

因此用户在 Prompt Hint 面板中修改文本，不会进入真正的发送链路。实际发送仍然由独立的 `composeWorkPrompt()` 自动构造。

这造成两个问题：

1. Prompt Hint 内容基于空消息生成；
2. 用户修改 Prompt Hint 后不影响最终提交内容。

必须让 Prompt Hint 直接绑定当前 Composer 输入：

```text
Composer Input
    ↓
Prompt Hint Preview
    ↓ 用户可修改
Effective Prompt
    ↓
Chat Controller Submit
```

---

## 2.4 Composer 仍然是普通 textarea

当前 `ChatComposer` 只包含：

* `<textarea>`；
* Send；
* Stop；
* Model Slot；
* Work Slot；
* Queue 数量。

而 copilot-desktop 的 `ChatInput` 包含：

* 自动高度；
* IME 输入保护；
* Prompt 历史；
* Slash Command；
* 虚拟化 Slash 菜单；
* 文件选择；
* 文件拖拽；
* 剪贴板文件；
* Attachment Tray；
* 文件解析状态；
* Voice Input；
* Context Gauge；
* Readiness 状态；
* Quick Ask；
* Model、Folder 等 Toolbar Extra；
* Imperative focus、clear、appendText、addFiles API。

v8.0.2 必须迁移原 `ChatInput`，不能继续扩展当前简化版 `ChatComposer`。

---

## 2.5 消息区域仍然是纯文本渲染

当前 `MessageList` 直接输出：

```tsx
<div className="message-content">{m.content}</div>
```

Reasoning、Tool、Clarify 和 Approval 也在同一个文件内用简单 `div` 渲染。

因此当前缺少：

* Markdown；
* GFM 表格；
* 代码高亮；
* Diff；
* 复制按钮；
* 消息时间；
* Agent Avatar；
* Streaming Orb；
* Media Token；
* 图片及文件附件；
* Tool 参数和结果展开；
* Tool 连续调用分组；
* Reasoning 折叠；
* Approval 自动检测；
* Agent Output 文件操作。

copilot-desktop 的 `MessageRow` 已实现 Markdown、代码、Diff、复制、头像、时间、附件、媒体和审批操作。

目标项目本身也已经存在完整的 `AgentMarkdown`，无需重新编写 Markdown Renderer。

---

## 2.6 Reasoning 和 Tool 组件只是薄包装且未使用

当前新增的 `ReasoningRow` 只是一个带 `Reasoning` 文本标签的普通消息块。

当前 `ToolActivityGroup` 只是逐行输出 Tool 状态，没有分组、折叠、参数、结果、附件和错误状态。

而 copilot-desktop 的完整实现支持：

* Reasoning 折叠；
* Thinking/Thought 状态；
* 连续 Tool Call 自动分组；
* Tool Call 与 Tool Result 按 `callId` 配对；
* 单项展开；
* Tool 参数预览；
* 输出行数；
* 文件附件；
* 失败状态；
* 100 次 Tool Call 不展开成 100 个独立气泡。

---

## 2.7 Prompt Navigator 没有接入 Chat

当前存在 `PromptNavigator.tsx`，但 `ChatSurface` 没有导入或渲染它。

因此此前要求的“右侧用户 Prompt 索引和快速定位”仍未完成生产接管。

## 2.11 附件状态存在，但没有输入入口

`ChatControllerState` 中定义了 `attachments`。

因此附件状态只是结构存在，用户无法从当前 Chat 输入框使用。

# 3. 产品目标

v8.0.2 完成后，Chat 必须达到以下状态：

1. **视觉结构与 copilot-desktop Chat 对齐；**
2. **复用原 Chat 核心组件，不再使用 Lite/Thin 替代实现；**
3. **保留 AI-OS 的 Expert、Team、Skill、MCP、Ask/Plan/Craft 能力；**
4. **Chat Core 不直接依赖 AI-OS Work 业务；**
5. **文件、模型、会话和 Runtime 均通过 Port 接入；**
6. **只保留 AI-OS WebOperator，不迁移 WebPreview；**
7. **实现真正的多 Chat 后台执行；**
8. **删除生产路径中的占位组件和无效完成标记。**

# 5. UI 交互要求

## 5.1 Header

保留：

* 当前 Active Expert 或 Team；
* Ask、Plan、Craft；
* 返回 Default；
* 当前运行状态。

调整：

* `ready` 状态不显示完整 TaskStatusBar；
* 只有 `creating/running/waiting/completed/failed` 才显示任务状态；
* Profile、Expert、Skill 不再重复显示两次；
* Usage 和 Duration 放入运行状态详情，而不是常驻占用两行。

## 5.2 Composer

Composer 应恢复为 copilot-desktop 的单一边框容器：

```text
┌─────────────────────────────────────────────┐
│ Attachment Tray                             │
│ Message input                               │
│ Error / Readiness                           │
│ 📎 🎤 | Expert Skill Permission Model ... ↑ │
└─────────────────────────────────────────────┘
```

禁止继续使用：

```text
Work Controls 独立一行
Model 独立一行
Textarea 独立一块
Send 独立在右下角
```

## 5.3 右侧面板

定义三个独立状态：

```ts
sessionFilesVisible: boolean
previewFileId: string | null
previewMaximized: boolean
```

规则：

* Session Files 默认隐藏；
* 有文件时显示未读数量；
* File Preview 只在选中文件时打开；
* Preview 支持拖动宽度；
* Preview 支持全屏覆盖 Chat Workspace；
* 没有打开任何面板时，不创建空白 `aside`。

## 5.4 Prompt Navigator

* 用户消息达到 2 条后显示；
* 默认折叠；
* 显示每条用户 Prompt 的首行摘要；
* 点击滚动至对应消息；
* 当前可见 Prompt 高亮；
* 与 File Panel 不能重叠；
* 窄窗口自动隐藏。
