# PRD v7.5.1 fixed：Copilot Desktop 调用 NoDeskClaw MCP Runtime Skill 固定路由修复方案

版本：v7.5.1 fixed
产品线：Copilot Desktop / Work 工作台 / Remote Experts
适用仓库：`ai-os-desktop / copilot-desktop`
目标后端：NoDeskClaw Expert MCP Gateway / Hermes MCP Skill Gateway
文档状态：实施 PRD / Cursor 可执行规格
核心目标：修正 Chat 页面 Expert + Skill 调用链路，脱离旧 `hermes-experts` / Expert Catalog 链路，统一改为 NoDeskClaw MCP `tools/list` + `tools/call` Runtime Skill 固定路由。

---

## 1. 背景

当前 Copilot Desktop 的 Chat 页面在选择 Expert + Skill 后，会进入旧 Expert Gateway 调用链：

```text
ComposerBar Send
  → useWorkExpertGatewaySend
  → workExpertGatewayApi.callExpertSkill
  → window.hermesExperts.callCatalogSkill
  → src/main/hermes-experts/expert-runtime.ts
  → ExpertMcpClient.callSkill
```

源码中 `useWorkExpertGatewaySend.ts` 当前仍调用 `workExpertGatewayApi.callExpertSkill()`。
`workExpertGatewayApi.ts` 当前仍构造 `OpenAICompatibleExpertPayload`，并调用 `window.hermesExperts.callCatalogSkill()`。
`preload/hermes-experts-api.ts` 暴露的 `callCatalogSkill`、`subscribeExpertTaskEvents` 等 API 仍属于 `hermes-experts:*` 旧 IPC 域。
`expert-runtime.ts` 当前会创建本地 `ExpertRun`，再通过旧 Expert MCP Client 调用远端。

但 NoDeskClaw v6.3.1 Runtime Skill 固定路由要求已经明确：

```text
Desktop 只能调用 NoDeskClaw MCP Gateway：
  POST /api/v1/hermes/mcp/skill-gateway
  method = initialize / tools/list / tools/call

Desktop 不允许 Runtime Skill 调用链继续使用：
  /api/v1/hermes-experts/*
  /api/v1/expert/*
  window.hermesExperts.callCatalogSkill
  workExpertGatewayApi.callExpertSkill
  ExpertGatewayClient.callSkill
```

附件要求的目标链路是：`copilot-desktop → NoDeskClaw MCP Gateway → JSON-RPC tools/list → JSON-RPC tools/call → HermesTask route_snapshot.route_type = hermes_api_server → Worker 调用 Hermes /v1/chat/completions → NoDeskClaw /hermes/tasks/{task_id}/events → result_url / artifact_url`。

因此，v7.5.1 fixed 的核心不是继续修补 `prompt is required`，而是彻底把 Runtime Skill 调用切换到 **NoDeskClaw MCP Runtime Skill 固定路由**。

## 4. 当前错误根因

### 4.1 `prompt is required` 的表层原因

当前 Chat 分支发送的是 OpenAI-compatible payload：

```json
{
  "model": "deepseek-v4-flash",
  "messages": [
    {
      "role": "user",
      "content": "分析陕西天基通信科技有限责任公司的客户画像"
    }
  ],
  "stream": true,
  "metadata": {
    "source": "copilot-desktop"
  }
}
```

但 NoDeskClaw Runtime Skill 固定路由要求 `tools/call.params.arguments` 只能是：

```json
{
  "prompt": "分析陕西天基通信科技有限责任公司的客户画像",
  "context": {
    "source": "copilot-desktop",
    "client_version": "v7.5.1",
    "device_id": "desktop-001",
    "conversation_id": "local-session-001",
    "workspace_id": "default",
    "ui_entry": "chat_composer"
  }
}
```

附件明确要求 Runtime Skill 的 `tools/call arguments` 只能包含 `prompt` 和 `context`，并禁止传入 `_routing / _execution / route_config / profile / route_type / orchestration_mode` 等路由字段。

### 4.2 更深层原因

真正问题不是缺少 prompt，而是调用入口走错：

```text
错误入口：
  window.hermesExperts.callCatalogSkill
  → hermes-experts 旧链路
  → expert_agent_event_stream
  → Hermes /v1/runs

正确入口：
  nodeskclawRuntimeSkillAPI.callRuntimeSkill
  → NoDeskClaw MCP tools/call
  → route_type = hermes_api_server
  → Hermes /v1/chat/completions
  → NoDeskClaw Task SSE
```

## 6. Runtime Skill Tool 过滤规则

NoDeskClaw `tools/list` 对 `source_type == hermes_api_server` 的 Skill 会返回 Runtime Skill metadata。Desktop 必须只允许调用满足以下条件的 tool：

```ts
function isRuntimeSkillTool(tool: McpTool): boolean {
  return (
    tool.sourceType === "hermes_api_server" &&
    tool.routeType === "hermes_api_server" &&
    tool.serverManagedRoute === true &&
    tool.defaultExecutionMode === "async_event" &&
    tool.sseTimelineEnabled === true &&
    tool.eventStreamProvider === "nodeskclaw_task_events" &&
    tool.artifactMode === "pull_only" &&
    tool.routeOverrideAllowed === false &&
    tool.routeHealth?.ok === true
  );
}
```

不满足条件的 tool：

```text
1. 不显示为可调用 Runtime Skill。
2. 不允许从 Chat 调用。
3. 可在调试页显示为 disabled，并展示原因。
```

## 9. Header 规范

Main Process 调用 NoDeskClaw MCP Gateway 时必须带：

```http
Authorization: Bearer <nodeskclaw_mcp_token>
Content-Type: application/json
x-client: copilot-desktop
x-client-version: v7.5.1
x-device-id: <desktop-device-id>
x-nodeskclaw-entry: runtime-skill
```

说明：

```text
1. token 只能由 Main Process 读取。
2. Renderer 不允许读取 token。
3. Renderer 不允许直接 fetch nodeskclaw API。
4. request_snapshot 依赖 header 和 arguments 构造诊断信息。
```

原产品规划也明确要求 token 仅由 Main Process 保存，Renderer 不直接访问 token 或 nodeskclaw API。

## 10. structuredContent 读取规范

MCP 成功响应后，Desktop 必须读取：

```ts
const structured = response.result?.structuredContent;
```

字段：

```ts
interface RuntimeSkillStructuredContent {
  task_id: string;
  task_no?: string;
  status: "queued" | "running" | "completed" | "failed" | string;
  execution_mode: "async_event";
  event_stream: string;
  result_url?: string;
  artifact_url?: string;
  artifact_mode?: "pull_only" | string;
}
```

最低校验：

```ts
if (!structured?.task_id) {
  throw new Error("Runtime Skill 未返回 task_id");
}

if (structured.execution_mode !== "async_event") {
  throw new Error(`Runtime Skill execution_mode 异常: ${structured.execution_mode}`);
}

if (!structured.event_stream) {
  throw new Error("Runtime Skill 未返回 event_stream");
}

if (!structured.event_stream.includes("/hermes/tasks/")) {
  throw new Error(`event_stream 不是 NoDeskClaw Task SSE: ${structured.event_stream}`);
}

if (structured.event_stream.includes("/v1/runs/")) {
  throw new Error(`Runtime Skill 不允许订阅 Hermes Run SSE: ${structured.event_stream}`);
}
```

附件要求 Desktop 必须读取 `response.result.structuredContent`，并使用 `task_id / event_stream / result_url / artifact_url` 等字段，而不是解析 `content[0].text`。

### 12.3 `runtime-skill-guards.ts`

```ts
export function isRuntimeSkillTool(tool: McpTool): boolean {
  return (
    tool.sourceType === "hermes_api_server" &&
    tool.routeType === "hermes_api_server" &&
    tool.serverManagedRoute === true &&
    tool.defaultExecutionMode === "async_event" &&
    tool.sseTimelineEnabled === true &&
    tool.eventStreamProvider === "nodeskclaw_task_events" &&
    tool.artifactMode === "pull_only" &&
    tool.routeOverrideAllowed === false &&
    tool.routeHealth?.ok === true
  );
}

export function assertRuntimeSkillTool(tool: McpTool): void {
  if (!isRuntimeSkillTool(tool)) {
    throw new Error(
      `Invalid Runtime Skill tool: ${tool.name}. Expected hermes_api_server async_event tool.`,
    );
  }
}

export function assertNoRouteOverride(arguments_: Record<string, unknown>): void {
  const forbidden = [
    "_routing",
    "_execution",
    "route_config",
    "agent_id",
    "agent_alias",
    "profile",
    "profile_id",
    "workspace",
    "workspace_id_override",
    "hermes_agent_instance_id",
    "hermes_instance_name",
    "route_type",
    "orchestration_mode",
  ];

  const hits: string[] = [];

  for (const key of forbidden) {
    if (key in arguments_) hits.push(key);
  }

  const context = arguments_.context;
  if (context && typeof context === "object" && !Array.isArray(context)) {
    for (const key of forbidden) {
      if (key in context) hits.push(`context.${key}`);
    }
  }

  if (hits.length > 0) {
    throw new Error(`Runtime Skill 禁止 Desktop 传路由字段: ${hits.join(", ")}`);
  }
}

export function assertNoHermesRunEventStream(eventStream: string): void {
  if (eventStream.includes("/v1/runs/")) {
    throw new Error(`Runtime Skill 不允许订阅 Hermes Run SSE: ${eventStream}`);
  }

  if (!eventStream.includes("/hermes/tasks/")) {
    throw new Error(`event_stream 不是 NoDeskClaw Task SSE: ${eventStream}`);
  }
}
```

### 13.2 暴露对象

```ts
export const nodeskclawRuntimeSkillApi = {
  listRuntimeSkills: () =>
    ipcRenderer.invoke("nodeskclaw:list-runtime-skills"),

  callRuntimeSkill: (input: CallRuntimeSkillInput) =>
    ipcRenderer.invoke("nodeskclaw:call-runtime-skill", input),

  subscribeTaskEvents: (input: SubscribeTaskEventsInput) =>
    ipcRenderer.invoke("nodeskclaw:subscribe-task-events", input),

  unsubscribeTaskEvents: (taskId: string) =>
    ipcRenderer.invoke("nodeskclaw:unsubscribe-task-events", taskId),

  onTaskEvent: (callback: (event: NodeskclawTaskEvent) => void) => {
    const handler = (_event: Electron.IpcRendererEvent, payload: NodeskclawTaskEvent) =>
      callback(payload);

    ipcRenderer.on("nodeskclaw:task-event", handler);

    return () => ipcRenderer.removeListener("nodeskclaw:task-event", handler);
  },

  onTaskStreamError: (callback: (event: NodeskclawTaskStreamError) => void) => {
    const handler = (_event: Electron.IpcRendererEvent, payload: NodeskclawTaskStreamError) =>
      callback(payload);

    ipcRenderer.on("nodeskclaw:task-stream-error", handler);

    return () => ipcRenderer.removeListener("nodeskclaw:task-stream-error", handler);
  },
};
```

### 16.3 发送流程

```ts
export function useRuntimeSkillSend(
  workContext: WorkChatContext,
  stream: StreamHelpers,
  taskStream: RuntimeTaskStreamHelpers,
) {
  const sendToRuntimeSkill = useCallback(async (input: {
    text: string;
    attachmentIds: string[];
    sessionId?: string | null;
    onComposerClear?: () => void;
  }) => {
    const tool = workContext.selectedSkill?.runtimeTool;
    if (!tool) return;

    const prompt = input.text.trim();
    if (!prompt && input.attachmentIds.length === 0) return;

    stream.appendLocalMessage({
      role: "user",
      content: prompt || "(attachments)",
    });

    stream.setExternalRunState("creating");
    stream.setLastError(null);

    try {
      const sc = await runtimeSkillApi.callRuntimeSkill({
        tool,
        prompt,
        sessionId: input.sessionId,
        workspaceId: "default",
        attachmentIds: input.attachmentIds,
      });

      stream.appendLocalMessage({
        role: "assistant",
        content:
          `**Runtime Skill task accepted**\n\n` +
          `- Task: ${sc.task_no ?? sc.task_id}\n` +
          `- Status: ${sc.status}\n`,
      });

      await taskStream.startStream({
        taskId: sc.task_id,
        taskNo: sc.task_no,
        eventSseUrl: sc.event_stream,
        artifactUrl: sc.artifact_url,
        resultUrl: sc.result_url,
        toolName: tool.name,
      });

      stream.setExternalRunState("streaming");
      input.onComposerClear?.();
    } catch (err) {
      const error = err instanceof Error ? err.message : String(err);

      stream.appendLocalMessage({
        role: "assistant",
        content: `**Runtime Skill error**\n\n${error}`,
      });

      stream.setLastError(error);
      stream.setExternalRunState("error");
    }
  }, [workContext, stream, taskStream]);

  return { sendToRuntimeSkill };
}
```

## 27. 版本结论

v7.5.1 fixed 的核心修复结论：

```text
不是修补旧 Expert Gateway。
不是继续兼容 OpenAI payload。
不是在 expert-runtime.ts 里补 prompt。
不是继续让 Chat 走 window.hermesExperts.callCatalogSkill。

而是新增 Runtime Skill Fixed Route Adapter：
  MCP tools/list 发现 Runtime Skill
  MCP tools/call 提交 prompt/context
  NoDeskClaw HermesTask 固定路由 hermes_api_server
  Main Process 代理 Task SSE
  Chat 页面展示 Timeline
  Artifact 通过 NoDeskClaw 消费
```

最终交付后，Copilot Desktop 的 Work Chat 调用远端专家 Runtime Skill 应进入以下稳定链路：

```text
Copilot Desktop Chat
  → NoDeskClaw MCP tools/list
  → Runtime Skill Tool
  → NoDeskClaw MCP tools/call
  → HermesTask(route_type=hermes_api_server)
  → Hermes /v1/chat/completions
  → NoDeskClaw Task SSE
  → Chat Timeline
  → result_url / artifact_url
```
