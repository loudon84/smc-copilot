# 源码复核结论

本次复核基于最新提交 `437d1d9080820c9ddb52438489512ef978ea98bc`。

v8.0.2 已经完成较大幅度的真实迁移：

* `ChatSurface` 已接入 `CopilotChatInput`、完整消息列表、富模型选择、Prompt Navigator 和按状态打开的右侧文件面板。
* File Platform 已从 `_upstream` 移入 `src/main/chat-files/platform`，Renderer Adapter 也开始调用 Platform Preview、搜索和 Context API。
* `MultiRunChatShell` 已经能够同时保持多个 Chat Host 挂载。

当前截图中的差距已经不是“原 Chat 组件没有迁入”，而是：

> **工作台状态、Chat Run 状态、Expert 上下文和 UI Header 仍然由多套状态源控制，导致布局重复、信息冲突和多会话隔离不完整。**

---

## 1. 当前源码中的主要问题

### 1.1 Chat 顶部存在两套 Header

`AiosCopilotChatHost` 同时渲染：

```tsx
<ChatHeader />
<HermesActiveExpertBar />
```

而两个组件都包含：

* 当前 Expert/Default 信息；
* Return Default；
* Ask / Plan / Craft。

`ChatHeader` 自身已经渲染一套 Ask/Plan/Craft。
`HermesActiveExpertBar` 又渲染一套 Ask/Plan/Craft。

这正对应截图中的两行重复区域：

```text
Expert 市场-资料分析       Ask Plan Craft
Active Hermes Default     Ask Plan Craft
```

### 1.2 Return Default 按钮当前没有功能

Host 传入的回调是空实现：

```tsx
onReturnDefault={() => {
  /* workspace clears active expert via HermesActiveExpertBar */
}}
```

所以截图顶部的 `Return Default` 按钮可见，但不会清除 Expert、Skill、Permission 或 Workspace 状态。

---

### 1.3 Expert 信息出现冲突并非单纯布局问题

当前同时存在两套上下文：

| 状态源                      | 保存内容                                                           |
| ------------------------ | -------------------------------------------------------------- |
| `useWorkChatContext`     | selectedExpert、selectedSkill、permissionMode                    |
| `HermesWorkspaceContext` | activeExpertId、activeTeamId、activeSessionId、workMode、profileId |

`useWorkChatContext` 使用组件本地 `useState` 保存 Expert 和 Skill，并没有同步到 Workspace。

但发送消息时：

* Prompt Hint 使用 `workContext.selectedExpert`；
* Header 使用 `workContext.selectedExpert`；
* Runtime Payload 的 `expertId` 却使用 `workspace.activeExpertId`。

因此可能出现：

```text
界面 Expert：市场-资料分析
Prompt Expert：市场-资料分析
Runtime expert_id：undefined / 另一个 Expert
Active Bar：Hermes Default
```

截图中的“市场-资料分析”与“Hermes Default”同时出现，就是这两套状态没有统一的直接表现。

---

### 1.4 当前 Multi-Run 只是 runId 隔离，业务上下文仍是全局的

`MultiRunChatShell` 会挂载多个 `AiosCopilotChatHost`，这部分方向正确。

但每个 Host 都读取同一个全局：

```ts
workspace.activeProfileId
workspace.activeSessionId
workspace.activeExpertId
workspace.activeTeamId
workspace.workMode
```

并且任意一个 Host 获得新 Session ID 后都会执行：

```ts
workspace.setActiveSessionId(id)
```

这意味着隐藏的后台 Run 仍可能被另一个 Run 修改：

* Profile；
* Session；
* Expert；
* Team；
* Work Mode。

当前 `ChatRunRegistryEntry` 只保存：

```ts
runId
sessionId
profileId
expertRunId
title
loading
unread
completed
```

没有保存 `expertId`、`teamId`、`skill`、`permissionMode`、`workMode`、`modelId` 和面板状态。

`ChatWorkspaceProvider.openRun()` 虽然接收 `expertId` 和 `teamId`，但注册时直接丢弃了这两个字段。

---

### 1.5 Run Tab 标题使用 Skill 名称，不是会话标题

Host 注册 Run 时使用：

```ts
title: workContext.selectedSkill?.name || "Chat"
```

所以截图中的 Tab 是：

```text
customer-profiling
```

它实际上是 Skill 名称，不是用户会话主题。

正确的 Tab 标题来源应是：

1. Session 已有标题；
2. 第一条用户 Prompt；
3. 后台自动生成标题；
4. 最后才使用 `New Chat`。

Expert 和 Skill 应作为 Badge 或 Tooltip，不应占用会话标题字段。

---

### 1.6 Composer 已完成组件迁移，但信息层级过密

当前 Composer Toolbar 的结构是：

```text
Attach
Voice
WorkComposerControls
PromptHintComposer
ModelPicker
Files Toggle
Context Gauge
Send
```

而 `WorkComposerControls` 又包含：

```text
Gateway
Expert
Refresh
Skill
Permission
Hermes MCP Host
Clear
```

这些控件全部被放入 `copilot-composer-toolbar-left`，该容器使用 `flex-wrap`。

所以在截图中，Composer 底部一行出现了十多个控制项。窗口稍窄后会自动折行，导致输入框高度和操作位置不稳定。

---

### 1.7 内容宽度没有统一

当前 CSS 中：

* Empty Suggestions 最大宽度：`720px`；

* Message 容器最大宽度：`920px`；

* Bubble 最大宽度：`720px`；

* Composer 只有左右 `16px` Margin，没有最大宽度；

* 右侧文件面板固定 `320px`。

因此截图中出现：

* Empty State 较窄；
* Composer 几乎铺满整个 Chat；
* 消息区域后续会采用另一套宽度；
* 三部分没有形成统一视觉中轴。

---

### 1.8 Run 状态尚未接入 Tab 状态

Host 在 `useEffect` 中始终注册：

```ts
loading: false
unread: false
completed: false
```

`ChatSurface` 没有向 Workspace 暴露：

```text
onRunStateChange
onTitleChange
onUsageChange
onUnreadChange
```

所以：

* Tab Spinner 不会随真实生成状态变化；
* 后台完成不会自动显示 Unread；
* `BackgroundRunIndicator` 缺少可靠状态；
* Session 标题无法回写 Tab。

---

### 1.9 文件系统仍存在双数据入口

当前文件列表和上传主要通过旧的 `window.chatFiles` Session Index，Preview 和部分 Context 操作通过新的 `window.chatFiles.platform`。

旧 `chat-files-ipc.ts` 仍然维护独立 JSON 索引和 UTF-8 Preview。

这会形成潜在不一致：

```text
附件上传记录 → Legacy Session Index
Preview Descriptor → Platform DB
Context Association → Platform Store
```

下一版本应统一到一个 File Facade。

---

### 1.10 E2E 仍然只是人工验收清单

当前 `chat-e2e-matrix.test.ts` 明确说明：

```text
NOT an automated E2E suite
```

并且测试仍然只校验验收场景数组长度。

因此当前无法自动验证：

* 两个 Run 是否串 Session；
* Expert 是否与 Runtime Payload 一致；
* Return Default 是否生效；
* 窄窗口 Composer 是否错位；
* 后台 Run 是否真正显示完成状态。

## FR-07 Prompt Hint 交互

Prompt Hint 改为图标按钮和 Popover。

状态：

```ts
type PromptHintState = {
  mode: "auto" | "custom" | "disabled";
  customValue?: string;
};
```

规则：

* 默认 `auto`；
* 用户编辑后进入 `custom`；
* 修改 User Prompt 时，`auto` 模式自动更新；
* `custom` 模式保持用户内容；
* 切换 Expert 或 Skill 后提示用户重置或保留；
* 发送后记录 effective prompt hash，不在 UI 显示完整系统提示词；
* 每个 Run 独立保存 Prompt Hint 状态。
