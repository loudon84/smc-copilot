# 源码复核结论

本次复核基于最新提交：

```text
f950b267f977ef0de501f4b8fee9f440b2cd83ea
PRD v8.1.1 : Runtime Closure
```

两个问题并不是单独的 UI 缺陷，而是同一个架构问题的两种表现：

> **Chat Workspace、Hermes Session 和 Sessions 页面分别使用三套状态源，目前没有统一生命周期和统一目录服务。**

---

## 一、问题 1：切换菜单后多个 Chat Tab 被清空

### 1. Chat 页面切换时被完整卸载

`HermesShell` 当前只渲染选中的页面：

```tsx
<HermesPageLoader pageKey={pageKey} />
```

当用户从 Chat 切换到 Sessions、Models 或其他菜单时，Chat 页面不是隐藏，而是直接卸载。

### 2. ChatWorkspaceProvider 位于 Chat 页面内部

当前结构是：

```text
HermesShell
└── HermesDefaultChatPage
    └── MultiRunChatShell
        └── ChatWorkspaceProvider
```

`ChatWorkspaceProvider` 被放在 `MultiRunChatShell` 内部，因此 Chat 页面卸载时：

* Provider 被销毁；
* 多个 `AiosCopilotChatHost` 被销毁；
* Chat Controller 被销毁；
* Tab 内存状态被销毁；
* Background Chat Host 不再保持挂载。

这与 v8.0.3 原定的“多个 Chat Host 保持挂载、后台继续运行”目标不一致。该能力目前只在用户停留于 Chat 菜单时成立。

### 3. 当前恢复只依赖 Renderer localStorage

Chat Workspace 当前保存到：

```text
chat-workspace-state.v1
```

而且：

* 只保存元数据；

* 保存失败被静默忽略；

* 没有 Main Process 持久化；

* 没有用户和 Workspace 命名空间；

* 没有数据库事务；

* 没有持久化写入确认。

重新进入 Chat 时，如果 localStorage：

* 没有成功写入；
* 反序列化失败；
* 被其他 Workspace 覆盖；
* 数据结构不完整；

`MultiRunChatShell` 会检测到 `runs.length === 0`，然后创建一个新的空白 Run，所以只剩下一个 `New Chat`。

---

## 二、需要明确：Chat Tab 不等于 Hermes Session

当前一个新 Tab 首先只是 `ChatRunRecord`：

```ts
identity: {
  sessionId: null
}
```

只有用户提交第一条消息并收到 `session.started` 后，才会绑定真正的 Hermes Session。

因此：

| 对象            | 含义                               |
| ------------- | -------------------------------- |
| New Chat Tab  | Workspace Draft Run              |
| 已发送第一条消息      | Hermes Session                   |
| Sessions 页面记录 | 已落入 Hermes `sessions` 表的 Session |

如果用户只是创建了两个空白 `New Chat`，Sessions 页面不显示它们是合理的；但这些 Draft Run 仍然应该在切换菜单后保留。

---

# 三、问题 2：Sessions 页面找不到历史会话

## 1. Sessions 页面读取的不是 Hermes Session 数据库

Sessions 页面调用：

```text
useHermesDefaultSessions
→ hermesDefaultApi.sessions.list()
→ window.hermesAPI.listCachedSessions()
```

`listCachedSessions()` 只读取：

```text
~/.hermes/desktop/sessions.json
```

它并不会实时查询 Hermes 的 `state.db`。

所以当前实际链路是：

```text
Chat 创建 Session
→ Hermes 写 state.db
→ sessions.json 不会自动更新
→ Sessions 页面读取旧缓存
→ 显示 No sessions
```

## 2. 页面首次进入只执行 refresh，不执行 sync

`useHermesDefaultSessions` 挂载时只调用：

```ts
refresh()
```

而 `refresh()` 只读取缓存。

只有用户主动调用：

```ts
sync()
```

才会从数据库同步到 `sessions.json`。

v8.1.1 的 Chat Runtime 完成一轮对话后，也没有接入 Session Cache 自动同步。

## 3. Session Cache 仍然固定读取默认目录

`session-cache.ts` 固定使用：

```ts
const DB_PATH = join(HERMES_HOME, "state.db")
```

`Sessions` 查询模块也使用相同固定路径。

这意味着它不能正确支持：

* 非 Default Profile；
* 多 Profile 同时运行；
* Profile 独立 `state.db`；
* Remote Profile；
* SSH Profile；
* v8.1.1 Profile-aware Runtime Store。

## 4. Sessions 页面打开会话的动作也没有接入多 Run Workspace

当前点击 Session 后只执行：

```ts
setActiveSessionId(s.id)
setActiveNavItem("chat")
```

但 `MultiRunChatShell` 只有在当前 Workspace 完全没有 Run 时，才会读取 `hermes.activeSessionId` 创建 Run。已有 Run 时，该 Session ID 会被忽略。

因此即使 Sessions 列表恢复，仍存在：

```text
点击历史 Session
→ 返回 Chat
→ 没有打开该 Session
```

的问题。

---

# 四、当前 E2E 没有覆盖这两条链路

v8.1.1 虽然加入 Playwright，但当前测试主要是结构断言。真正 Electron Window 测试只有设置：

```text
E2E_ELECTRON_WINDOW=1
```

才会运行，否则直接跳过。测试也没有覆盖菜单切换、Tab 恢复和 Sessions 列表。

# 4. Chat Workspace 生命周期

## FR-01 Provider 提升

将：

```tsx
<MultiRunChatShell>
  <ChatWorkspaceProvider>
```

调整为：

```tsx
<HermesDefaultProvider>
  <HermesWorkspaceProvider>
    <ChatWorkspaceProvider>
      <HermesShell />
    </ChatWorkspaceProvider>
  </HermesWorkspaceProvider>
</HermesDefaultProvider>
```

`MultiRunChatShell` 不再创建 Provider，只消费 Workspace Context。

## FR-02 Chat Workspace 常驻挂载

`HermesShell` 调整为：

```tsx
<main className="hermes-center">
  <PersistentChatWorkspace
    visible={pageKey === "chat"}
  />

  {pageKey !== "chat" ? (
    <HermesPageLoader pageKey={pageKey} />
  ) : null}
</main>
```

隐藏 Chat 时：

```css
.chat-workspace--hidden {
  visibility: hidden;
  pointer-events: none;
  position: absolute;
  inset: 0;
}
```

不能使用条件渲染删除 Chat 组件。

## FR-03 后台运行

用户停留在 Sessions、Models 或 Skills 页面时：

* Agent Streaming 继续；
* Tool Call 继续；
* Approval 状态保持；
* Queue 继续；
* Unread 状态更新；
* 完成通知正常触发；
* 返回 Chat 后直接显示最新内容。

# 5. Main-owned Chat Workspace Store

localStorage 不再作为权威数据源。

## 5.1 数据库

新增桌面级数据库：

```text

```

不能放入某一个 Profile 的 `state.db`，因为一个 Workspace 可以同时包含多个 Profile Run。

## 5.2 表结构

```sql
CREATE TABLE chat_workspace (
  workspace_id TEXT PRIMARY KEY,
  active_run_id TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL

CREATE TABLE chat_workspace_run (
  run_id TEXT PRIMARY KEY,
  workspace_id TEXT NOT NULL,
  profile_id TEXT NOT NULL,

  title TEXT NOT NULL,
  title_source TEXT NOT NULL,

  mode TEXT NOT NULL,
  expert_id TEXT,
  expert_name TEXT,
  team_id TEXT,
  team_name TEXT,
  skill_name TEXT,

  work_mode TEXT NOT NULL,
  permission_mode TEXT NOT NULL,
  model_id TEXT,

  run_state TEXT NOT NULL,
  draft TEXT,

  files_visible INTEGER NOT NULL DEFAULT 0,
  preview_file_id TEXT,
  preview_maximized INTEGER NOT NULL DEFAULT 0,

  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  closed_at INTEGER
);
```

## 5.3 Workspace API

新增：

```text
chat-workspace:list

chat-workspace:set-active

```

所有写入由 Main Process 完成。

Renderer Context 作为视图状态缓存，不再作为最终存储。

# 6. Draft Run 与 Session 区分

## 6.1 Run 类型

```ts
type ChatWorkspaceRunKind =
  | "draft"
  | "session";
```

判定规则：

```text
sessionId == null
→ draft

sessionId != null
→ session
```

## 6.2 Draft 行为

Draft Run：

* 显示在 Chat Tabs；
* 切换菜单后保留；
* 应用重启后恢复；
* 不进入正式 Sessions 列表；
* 可以在 Sessions 页面单独显示为 Drafts；
* 长期未使用可自动清理。

## 6.3 Session 绑定

收到：

```text
session.started
```

后在一个事务中完成：

```text
更新 workspace_run.session_id
→ kind 从 draft 变 session
→ 更新 title
→ 广播 workspace.changed
→ 广播 session-catalog.changed
```

```text

→ setActiveNavItem("chat")
```

```ts
chatWorkspace.openSession({
  profileId,
```

```text
├── 已存在 Run → 激活现有 Tab
```

# 12. Chat 页面恢复流程

进入应用时：

```text
1. ChatWorkspaceProvider 调 Main getSnapshot
2. 恢复 Run 顺序
3. 恢复 Active Run
4. 为每个 Session Run 加载历史
5. 为未完成 Run 执行 Runtime Recovery
6. 恢复 Draft、Model、Expert 和面板状态
7. 开始订阅 workspace.changed
```

加载期间显示：

```text
Restoring chat workspace…
```

如果某个 Session 已不存在：

```text
Session unavailable
[Remove tab] [Open diagnostics]
```

不能直接删除 Tab。
