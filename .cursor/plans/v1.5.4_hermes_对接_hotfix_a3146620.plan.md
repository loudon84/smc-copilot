# v1.5.4 Hermes Model Catalog & Desktop Runtime SSE Chat Closure

## 现状结论（已勘察）

- Runtime [instance_chat_service.py](services/runtime/src/services/instance_chat_service.py)：`list_models()`(L79-130) 走 Gateway `/v1/models`；`ensure_default_model_config()`(L150-222) 优先 `/v1/models` seed → 写入 `smc-copilot`
- [client.py](services/runtime/src/integrations/hermes/client.py) 仅有 `list_models()`(L268)，无 `/api/model/options`
- `HermesLocalConfigService.read_config()`（v1.5.3 已有）可直接读 `~/.hermes/config.yaml`
- [runtime_status_service.py](services/runtime/src/services/runtime_status_service.py) L190-241 已输出 `execution.chatReady` —— Goal B 服务端前提已满足，无需改 Runtime readiness
- Desktop [desktop-boot-coordinator.ts](apps/desktop/src/main/startup/desktop-boot-coordinator.ts) L35-41 dev 模式仍调 `autoStartCopilotServeIfReady()`
- [runtime-connection-manager.ts](apps/desktop/src/main/copilot-runtime-client/runtime-connection-manager.ts) `probeHealth()`(L104) 只返回 boolean；handshake 已拉取并缓存 readiness
- [ServeChatRuntimeAdapter.ts](apps/desktop/src/main/runtime-adapters/ServeChatRuntimeAdapter.ts) L44-46 `ready` 仅看 `connection.ready`
- Chat ModelPicker → [aiosModelsAdapter.ts](apps/desktop/src/renderer/src/modules/chat/adapters/aios/aiosModelsAdapter.ts) → `window.hermesDefaultChat.listModels`（本地 models.json，§44 禁止）；Main 侧 [configuration-client.ts](apps/desktop/src/main/copilot-runtime-client/clients/configuration-client.ts) 已封装 `/chat/model-options` + `/chat/model-config` 可复用

## Phase 1 — Runtime Model Catalog（PRD §8-17, §49, §51）

1. [client.py](services/runtime/src/integrations/hermes/client.py) 新增 `list_model_options(*, refresh: bool = False) -> dict`：`GET /api/model/options`（`refresh=1` 透传），复用 `_auth_headers()`；`list_models()` 保留但注释标注「Gateway Virtual Models only」
2. 新增 [hermes_model_catalog_service.py](services/runtime/src/services/hermes_model_catalog_service.py)：normalize `/api/model/options` → `RuntimeChatModel`（§15：id/label/provider/baseUrl/available/isDefault/capabilities 仅映射 Hermes 实际字段，不猜测）；`resolve_default_model(profile_name)` 经 `HermesLocalConfigService` 读 config.yaml `model.provider/model.default/model.base_url`
3. [schemas/chat.py](services/runtime/src/schemas/chat.py)：`ChatModel` 增 `available/is_default/capabilities`，`source` 枚举化（`hermes-model-options`/`hermes-config`/`gateway`）；`ChatModelListResponse` 增 `default_model{provider,modelId}` 与可选 `gateway.virtualModel`；保持 `is_current` 兼容
4. `InstanceChatService.list_models()` 改走 catalog service；[instance_chat.py](services/runtime/src/api/v1/instance_chat.py) `/chat/models` 增 `refresh: bool = Query(false)` 透传；`/chat/model-options` 同语义
5. [core/errors.py](services/runtime/src/core/errors.py) 增错误码 `HERMES_MODEL_OPTIONS_UNAVAILABLE` / `HERMES_MODEL_CONFIG_INVALID` / `HERMES_DEFAULT_MODEL_NOT_FOUND` / `MODEL_CATALOG_PARSE_FAILED`；`/v1/models` 可用而 `/api/model/options` 不可用时报 Model Catalog Degraded 而非 Gateway down
6. §20 一致性：config 默认模型不在动态 catalog 时追加 `available=false, source=hermes-config, isDefault=true` 条目
7. 运行 `npm run contracts:generate` 重新生成 `contracts/runtime-api/openapi.yaml` + TS client

## Phase 2 — 默认模型 SOT 修正（PRD §18-19, §50）

- `ensure_default_model_config()` 删除 `/v1/models` seed 分支，改由 `HermesModelCatalogService.resolve_default_model()`（config.yaml SOT）seed；`get_model_config()` 返回 `source=hermes-config` 语义
- `resolve_default_model()`（L300）不再 fallback 到 `list_models()[0]`（虚拟模型）

## Phase 3 — 历史数据 Reconcile（PRD §21-22）

- 读取 model-config 时一次性 reconcile：`existing.model_id ∈ Gateway /v1/models`（虚拟模型）且 config.yaml 有真实默认 → 覆写为真实执行模型；`provider=custom` 等真实用户选择不动
- 可选：§23 Instance Diagnostics 增 `modelCatalog{gatewayVirtualModel, defaultExecutionModel, availableModels, catalogSource, configSource}` 摘要字段

## Phase 4 — Desktop Boot 改造（PRD §25-29）

- [desktop-boot-coordinator.ts](apps/desktop/src/main/startup/desktop-boot-coordinator.ts)：删除 `canSpawnCopilotServe` + `autoStartCopilotServeIfReady()` 调用，仅 `initCopilotRuntimeConnection()`；`repairRuntimeConnection()`（用户显式 Repair）保留
- `runtime-connection-manager.ts` `probeHealth()` 改为结构化 `RuntimeHealthProbeResult{reachable,url,httpStatus,serviceStatus,latencyMs,errorCode,errorMessage}`（§27-28：HTTP 2xx 且 body.status=="ok"）；启动日志打印 baseUrl/healthUrl + `COPILOT_SERVE_URL/COPILOT_RUNTIME_URL/COPILOT_SERVE_PORT` configured 布尔（不打印 secret）
- `canSpawnCopilotServe` 函数本身保留（repair 路径仍用），但 boot 不再引用

## Phase 5 — Runtime Connection State 拆分（PRD §30-33, §52）

- [runtime-state-contract.ts](apps/desktop/src/shared/copilot-runtime/runtime-state-contract.ts)：`RuntimeConnectionState` 增 `reachable/serviceReady/executionReady/chatReady/maintenanceReady`；`ready = serviceReady`（legacy 兼容）
- `runRuntimeHandshake()` 从 cached readiness 填充拆分字段；[runtime-capability-manager.ts](apps/desktop/src/main/copilot-runtime-client/runtime-capability-manager.ts) 增 `isRuntimeServiceReady()/isRuntimeChatReady()` 等拆分缓存访问器（§39）
- `maintenance.ready=false` 不阻塞 Chat（§32-33：现状已是，补测试锁定）

## Phase 6 — Chat Adapter 门控（PRD §38-43, §53）

- `ServeChatRuntimeAdapter.ready` 改为 `connection.serviceReady && cachedReadiness.execution?.chatReady === true`；readiness 缺失时 fail closed → `RUNTIME_UNAVAILABLE`
- [chat-runtime-ipc.ts](apps/desktop/src/main/chat-runtime/chat-runtime-ipc.ts)：legacy-direct 分支加 `@deprecated legacy-direct development fallback` 注释；生产模式 `isLegacyHermesDirectAllowed()` 已恒 false（保持，不物理删除旧代码）
- Chat Send 未选模型时 `modelId` omitted（§47），不发 `smc-copilot`；显式 override 仅在具备 provider+modelId 时发送（§48）

## Phase 7 — Model Picker 数据源切换（PRD §44-46）

- Main 新增 chat models IPC（走 `configurationClient.listModelOptions/getModelConfig`，resolve default instance），Preload + `index.d.ts` + `docs/API_CONTRACTS.md` 同步
- [aiosModelsAdapter.ts](apps/desktop/src/renderer/src/modules/chat/adapters/aios/aiosModelsAdapter.ts)：Serve transport preferred 时改走 Runtime IPC；`COPILOT_ALLOW_LEGACY_HERMES_DIRECT=true` 开发模式回退 `hermesDefaultChat`；Runtime 不可用时 fail closed
- 不新增模型切换持久化能力（§46），仅保证真实目录 + 当前默认正确展示
